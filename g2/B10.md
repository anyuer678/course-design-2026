## 三、独立修改任务（README 练习建议原文；做完跑 `run.bat` 全绿）

1. （练习建议 1）把页式快照从"整库重写"升级到**行/索引增量分页**：B+ 树页落盘、根页号写进头槽位、 CHECKPOINT 只写脏页——先量一次"改了 1 行要写多少页"，再决定值不值。
2. （练习建议 2）把 UPDATE 的日志从"整表镜像"改成"前后镜像 + LSN"，恢复时按 LSN 幂等重放 （现在只保证不重放旧记录，还做不到单条幂等）。
3. （练习建议 3）给 WAL 加**组提交窗口**（攒 N 条或 T 毫秒一次 fsync），用 demo 第 7 段的 计量方法量"吞吐 vs 崩溃窗口"的取舍。
4. （练习建议 4）实现 `COUNT(*)`/`SUM(col)` 与 `GROUP BY`，注意它们要在投影之前算。
5. （练习建议 5）支持 `LEFT JOIN`：内表无匹配时补 NULL，并想清楚 `ON` 与 `WHERE` 的差别 （谓词下推会把 LEFT 退化成 INNER）。

### 延伸坑单（README 踩坑原文，任选一条复现）

- **`UPDATE ... SET 主键 = 新值` 会悄悄弄坏索引**：只改 `rows` 不删旧键，
- **多行 INSERT 中途失败留下半条语句**：第一行已写进内存、日志却没写，
- **CHECKPOINT 落下未提交数据**：快照写的是"当前内存"，而事务中的改动已经在
- **事务里的 DDL 回滚不掉**：快照只存行数据的话，事务里 `CREATE TABLE` 建的表
- **WAL 最后一行撕裂会让整个库打不开**：崩溃时半条 JSON 记录被追加进去，
- **Windows 的 `\r\n` 让按字节截断砍错位置**：文本模式读出来的行数 ≠ 字节数，
