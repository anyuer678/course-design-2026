## 二、知识点速览（README 表格原文）

| 课程知识点 | 代码 | 验证方式 |
|---|---|---|
|---|---|---|
| 单线程串行化=原子性 | `server.py` selectors 循环 | 两客户端交替 `INCR` 得 1、2（无锁也不会丢更新）；同循环里坏包只伤自己 |
| 流式解析（粘包/拆包） | `FrameDecoder` 累积缓冲 | 同一字节流按 1..9 随机块长喂入 ×20，帧序列与整体喂入逐条相等 |
| 内联与数组混合 | `_cut_command` 双通道 | 同一条流里 `PING\r\n`、`*2\r\n$3\r\nGET...`、带引号内联并存；`*0`/空行跳过 |
| 二进制安全 | 显式长度定界 | 值含 `\r\n\0` 全程往返无损（请求与回复方向都测） |
| 协议错误分类 | `ProtocolError` 文本 | 六类错误文本逐字断言，且与第二解析器**消息一致** |

## 三、独立修改任务（README 练习建议原文；做完跑 `run.bat` 全绿）

1. （练习建议 1）给主动过期加"时间触发"通道（与命令计数并行：`select` 每次循环检查上次周期距今超过 T 秒就触发），用假时钟写测试——顺便说清"为什么真实 Redis 需要它"（空闲时也清内存）。
2. （练习建议 2）给复制加**复制积压缓冲**：主库保留最近 N 字节的流，重连时若从库偏移落在缓冲内就 只补发增量（部分重同步的雏形）；先改 case-study §8.2 的偏差表再动代码。
3. （练习建议 3）给快照加一个"版本升级"场景：改 `MAGIC` 尾部版本号，让加载器对旧版本给出**可操作**的 错误信息（而不是一句"魔数不符"）；再想想向前兼容该怎么做。
4. （练习建议 4）用 selectors 实现 per-connection 空闲超时（30 秒无请求断开），说明它与 Redis `timeout` 配置的差别（后者还涉及主从/发布订阅的连接豁免）。

## 四、失败复现任务（先写下「我预言哪条会红、为什么」，再动手）

复现坑 1：让客户端用 **int** 参数发 `EXPIRE k 10`（被编成 `:10` 整数帧），跑脚本——为什么"探针用字符串全过、脚本用 int 全挂"会把排查带偏？教训"先打印自己发出去的字节"接下来怎么用？

> 出处：踩坑 1（int 参数编成 RESP 整数帧）。对不上预言本身就是收获。

### 延伸坑单（README 踩坑原文，任选一条复现）

- **"时好时坏"的冒烟：客户端把 int 参数编成了 RESP 整数帧**。`c.cmd("EXPIRE","k",10)`
- **协议错误断开前必须把错误帧发完**（真实 Redis 的 CLOSE_AFTER_REPLY 模式）：
- **Windows 的 RST ≠ 优雅 EOF**：服务器关连接时客户端可能收到 `ConnectionResetError`，
- **构造失败不能泄漏监听套接字**：坏快照拒启时 `__init__` 里已 bind 的 socket 要关
- **单线程服务器里"任何未捕获异常=全体瘫痪"**：调试初期 `CommandError.message`
