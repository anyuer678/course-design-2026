## 一、口述提纲（不看代码讲得出）

1. 四组对照（SQL 注入 / XSS / 口令存储 / 路径穿越）各自的"漏洞版为什么坏、修复版为什么好"？

3. 上下文相关转义：四种上下文（文本/属性/JS/href）各防什么载荷？
4. 静态扫描器 + 人工登记表的"双向比对"：把包装函数从 sink 摘掉会怎样？

## 二、知识点速览（README 表格原文）

| 课程概念 | 落在哪里 | 怎么被验证 |
|---|---|---|
|---|---|---|
| 注入 = 数据获得语法身份 | 四组并排的 vuln/fixed | 每组都有"漏洞版拿到不该拿的、修复版拿不到"的成对断言 |
| 参数绑定 vs 拼接 | `login_*` / `search_*` | 注释截断（`admin' --`）在拼接版登入 admin、绑定版被拒；UNION 泄漏 2 行 vs 0 行 |
| 载荷成立需要**语法条件** | `PAYLOAD_UNION` 的列数、`--` 收尾 | 列数不对 → `OperationalError`；课本那条 `' OR '1'='1` 因 AND 优先级**在本谓词里不成立**（也写成断言） |
| 标识符不能绑定 | `order_bound` / `order_whitelist` | 绑参列名是**静默无效**（与无排序同序、≠ 真排序）；白名单对合法输入结果不变，对载荷 `COLUMN_NOT_ALLOWED` |
| 二阶注入：危险的 sink 不是 source | `note_report_*` | 安全写入 + 拼接读取 → 泄漏散列；同一数据绑定读取 → 只剩正文 |

## 三、独立修改任务（README 练习建议原文；做完跑 `run.bat` 全绿）

1. （练习建议 1）把 `login_bound` 改回拼接，跑测试：哪几条先红？错误信息能不能指出"数据拿到了语法身份"？
2. （练习建议 2）给 `order_whitelist` 加一个合法列（比如 `phone DESC` 的第二种写法），说明为什么加列不用改 SQL。
3. （练习建议 3）在 `xss.py` 里新增一个"`<script>` 里直接用 `html.escape`"的修复版，构造一条能打破它的载荷并写测试。
4. （练习建议 4）把 `creds.DEFAULT_ITERS` 从 120k 调到 1k，说出哪几条断言会红、为什么它们该红。
5. （练习建议 5）给 `traversal` 加一条"尾随空格"载荷（`ok.txt `），解释为什么修复版会拒它、而这条拒绝的代价是什么。
6. （练习建议 6）把 `audit.JUDGED` 里 `order_whitelist` 的定性改成"危险"，看 `problems()` 是否点名——这就是"登记表不是装饰"。
