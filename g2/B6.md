## 二、知识点速览（README 表格原文）

| 课程知识点 | 代码 | 验证方式 |
|---|---|---|
|---|---|---|
| 两指针反转 | `asm_reverse` | 手算 7 例（含空串/单字符）；**越界哨兵围栏**（只许动指定 5 字节）；60 组对拍 `std::reverse` + 翻两次还原 |
| len 语义与边界 | 同上 | len≤0 不动内存；指针为空的 0 长调用安全（测试直接传 `nullptr,0`） |
| 迭代斐波那契 | `asm_fib` | 手算 0..10；fib(93)=12200160415121876738（u64 边界）；**0..93 全量与 C++ 参照对拍**；负数=0 |
| 比例变址寻址 | `asm_sort` | 手算 4 例（空/单/逆序/重复）；**60 组对拍 `std::sort`**（值域故意窄、重复多） |
| 完整栈帧 | `asm_sum_positive` | 手算 4 例 + 60 组参照对拍；**反汇编 6 项结构断言**（push rbp / mov rbp,rsp / leave / ret / push rbx / pop rbx） |

## 四、失败复现任务（先写下「我预言哪条会红、为什么」，再动手）

把一个 C++ 侧参数从 `long long` 改回 `long`（坑 1 的现场），跑自测——是编译期报错、还是运行时段错误？这说明"宽度"该写在契约的哪里？

### 延伸坑单（README 踩坑原文，任选一条复现）

- **Windows x64 陷阱一：参数宽度**。C++ 侧写 `long len`（32 位），传 `-3` 进 rdx 是
- **陷阱二：数组步长**。`asm_sort` 按 8 字节步长寻址，测试却传 `long` 数组（4 字节元素）
- **`leave` 把 `pop rbp` 折进去了**：反汇编检查第一版要求显式 `pop rbp`，于是 FAIL——
- **`mov rbx, imm64` 反汇编成 `movabs`**：检查器正则漏认 mnemonic，被自己的输出当场纠正。
- **objdump 不认含中文的绝对路径**（`Illegal byte sequence`）：工具里改为
- **探针的指针宽度**：`reinterpret_cast<long>(buf)` 在 x64 上装不下指针（编译期报错），
