## 二、知识点速览（README 表格原文）

| 课程知识点 | 代码 | 验证方式 |
|---|---|---|
|---|---|---|
| 数据与视图分离 | trace JSON（数据） vs page.py（视图） | 页面内嵌数据**逐字节等于** JSON 文件（extract + json.loads + 相等断言） |
| "演的是真算法" | `replay.replay_sort` | 20 事件**逐步重建**：每个 swap 后逐位等于快照、pop 取出的必须是当时堆顶、build 后堆序成立；负面自证：改坏一条快照必须报错 |
| BFS/DFS 语义对拍 | `replay.reference_bfs/dfs` | Python 独立实现产出**同口径**逐步记录（visit + 队列/栈快照），与 C++ 导出逐访问相等；b 字段与独立算的距离相等 |
| 状态机驱动的交互 | page.py 的 `makeAnimator` | 播放/暂停/单步/上一步都只是下标移动；结构断言（控件 id 齐备） |
| 自包含与确定性 | `build_page` | 同一 inputs 两遍构建**字节相同**；无网络请求、无随机数 |

## 三、独立修改任务（README 练习建议原文；做完跑 `run.bat` 全绿）

1. （练习建议 1）给导出器加 BST 场景（借 B2 的 `ds::bst.hpp` 也加同款 trace 口），在页面加第三张卡片—— 先把"节点/边快照"的记录格式定死，再写渲染；体会"数据格式先行"。
2. （练习建议 2）把 `makeAnimator` 的下标搬进 URL hash（`#step=7`），刷新页面能回到同一帧， 说明"状态可寻址"对分享与复现的价值。
3. （练习建议 3）加"逐步解释"文本框：每一步把 `op` 翻成一句人话（建堆/交换 k/v/取出最小值）， 再想想"解释文本应该由导出器生成还是页面生成"（提示：谁掌握上下文）。
4. （练习建议 4）用 `performance.now()` 给播放循环加丢帧统计（数据量大时动画会追不上）， 说清"动画的时基"和"算法的步数"是两回事。

### 延伸坑单（README 踩坑原文，任选一条复现）

- **`echo` 里的 `->` 又双叒踩了**（仓库已记过两次：B7、B10）：run.bat 的
- **回放协议必须"读源码得来"**：`Heap::pop` 里"根<->尾交换 + 丢尾"这步是**未记录**的，
- **"每帧长度都等于 n"是假假设**：取出过程中有一帧"在途"（元素已离开堆、还没进前缀），
- **跨项目 include 用正斜杠**：`-I..\B2-datastruct-lab\include` 里的反斜杠会被 bash 当转义吃掉，
