## 〇、这张卡对应什么（README 原文）

> **shell 是进程课的总复习**——一行命令背后是 fork、exec、pipe、dup2、waitpid 的

## 一、口述提纲（不看代码讲得出）

1. fork / exec / waitpid 的次序与逐 pid 回收；僵尸是怎么被 /proc 数出来的？
2. 管道端点的关闭语义：父不关写端，下游凭什么等不到 EOF？
3. stdio 预读为什么会吞掉子进程的 stdin——逐字节 read 换来了什么？
4. `$?` 的口径：三段管道整体 = 最后一段；`exit` 无参数 = 上一条的 `$?`。

## 二、知识点速览（README 表格原文）

| 课程知识点 | 代码 | 验证方式 |
|---|---|---|
|---|---|---|
| fork + execvp | `run_pipeline` 子进程分支 | `true/false/sh -c 'exit 42'` 的退出码实测；找不到命令 → stderr + 127 且 shell 继续 |
| 管道 = N 进程 + N-1 根 pipe | `pipe()`/`dup2`/端点关闭 | 两段/三段管道现场（`printf \| sort \| head`）；父进程**关掉多余端点**（不关会挂死） |
| 重定向是 dup2 的艺术 | 子进程 `open`+`dup2` | `>` 截断、`>>` 追加、`<` 读入、管道+落盘组合；坏路径报错但 shell 继续 |
| 内建命令（改自己） | 单命令时 shell 本体执行 `cd/exit/pwd` | `cd /tmp` 后 `pwd` 变、跨行保持；**管道里的 cd 按外部命令处理**（找不到 → 127）有专项用例 |
| 退出码口径 | `waitpid` + `WIFEXITED/WIFSIGNALED` | `$?`=最后一段（`true \| false` → 1）；信号死亡 = 128+15=143；`exit N` 显式码 |

## 三、独立修改任务（README 练习建议原文；做完跑 `run.bat` 全绿）

1. （练习建议 1）加 `&` 与 `jobs`：后台子进程不 wait，另存 pid 表；说明"后台任务"为什么必须改回收逻辑 （SIGCHLD / WNOHANG 轮询），以及僵尸检查要跟着改什么。
2. （练习建议 2）加 `&&` 与 `||`：把"单行多命令"从管道的两层语法里切出来，画出你改了哪一层。
3. （练习建议 3）给 `lex` 加反斜杠转义与 `$VAR` 展开（只做最小子集），说清"展开发生在词法之后、 执行之前"的位置。
4. （练习建议 4）用 `strace -f -e trace=process,desc ./build/msh` 跑一段管道，对着 trace 数 fork/pipe/dup2/wait4 的次序，和 `run_pipeline` 的代码逐行对上。

把 `read_line` 的空行返回值（0）当成 EOF（坑 1 的真 bug），跑测试——哪条测试先红？为什么"第一行是空行"会让整个 shell 退出？

> 出处：踩坑 1（"空行 = EOF"的真 bug）。对不上预言本身就是收获。

### 延伸坑单（README 踩坑原文，任选一条复现）

- **"空行 = EOF"的真 bug**：`read_line` 对空行返回 0，而主循环把 `<=0` 当 EOF——
- **stdio 预读会吞掉子进程的 stdin**：最初想用 `fgets` 读命令行——缓冲会把 `cat`
- **管道端点必须关干净**：父进程不关写端，下游的读端等不到 EOF——整条管道挂死。
- **两条我写错的测试期望**（实现是对的）：管道 `$?` 口径是**最后一段**（`cd /tmp | cat`
- **WSL 默认发行版是 docker-desktop**（没有 bash）：必须 `-d Ubuntu-24.04` 点火，
- **命令替换吞退出码**：`out=$(python3 ...)` 里若测试失败，`set -e` 不会拦住
