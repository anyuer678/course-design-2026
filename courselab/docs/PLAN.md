# 课程项目平台（CourseLab）· 方案书

> 毕设级工程。规模对标参照（CCZX/wechat：多应用、17+ 功能点、数百次提交、真实可部署），
> 但**不做它的聊天功能**——本项目的题目是：**每个课程各有一个小型项目平台**，
> 用一份统一底座承载，另有门户与管理端。
> 本目录独立于课设治理（showcase/g2/check_all/scan_refs 都不扫描这里）；每轮结束本地提交。
>
> **开工规格见 `docs/DESIGN.md`**（多端三端 / 18 个功能点 F1-F18 / 页面路由 / 数据模型 / API 草案 /
> 部署设计；里程碑与功能点的映射也在那里）。

## 一、定位（一句话）

把工作区里散落的"课程项目群"（33 个项目 + 自包含展示页 + 本地实验台 + 练习册）
升格为一个**可登录、可浏览、可在线运行、可管理、能部署**的 Web 平台：
平台按课程组织，每门课程独享一个"小型项目平台"（课程页/项目页/在线演示/实验台/练习）。

## 二、与现状的关系（内容源 vs 平台，不造第二份数据）

| 现状（课设仓库里的） | 在平台里的角色 |
|---|---|
| `projects/` 33 个项目 | 内容源：课程 → 项目 → 在线演示 |
| `showcase/*.html` 自包含展示页 | 每个项目页的"在线演示"内容（嵌入或跳转） |
| `showcase/lab.py` 实验台（固定命令表 + 日志环） | "在线实验"能力的雏形，平台化（多用户/权限/队列/审计） |
| `g2/` 练习册 40 卡 | "练习任务"体系的内容源（领取/完成记录） |
| `showcase/manifest.json` + 各 README | 课程目录与项目元数据的**现算**来源（口径唯一） |

## 三、角色与权限（矩阵先写，服务端唯一判定源）

| 能力 | 访客 | 学生 | 教师 | 管理员 |
|---|---|---|---|---|
| 浏览课程/项目/演示 | 可 | 可 | 可 | 可 |
| 注册 / 登录 | 注册 | 登录 | 登录 | 登录 |
| 在线实验（跑演示/测试） | 否 | 可（限流） | 可 | 可 |
| 练习任务 | 否 | 领取/提交 | 布置/查看本课 | 全量 |
| 课程/项目管理 | 否 | 否 | 本课 | 全量 |
| 用户/审计/统计 | 否 | 否 | 本课统计 | 全量 |

沿用课设仓库纪律：**判定只有一份**（本表落成服务端模型，页面只读判定结果，不重复规则）。

## 四、功能面（分端，按毕设规模展开）

**学生端（门户 + 课程工作区）**
1. 首页：平台概览（课程数/项目数/在线运行数）+ 课程目录（批次/领域筛选、搜索）
2. 课程主页：课程简介、项目清单、资料、练习任务
3. 项目页：详情（一句话/知识点/踩坑摘要）＋ 在线演示（既有 showcase）＋ 实验台（跑演示/测试/启服务、实时日志）
4. 个人主页：我的任务、我的实验记录
5. 站内搜索（课程/项目/任务）

**管理端**
1. 课程 / 项目管理（上架、排序、关联项目与任务模板）
2. 用户管理（注册审批、角色、封禁）
3. 实验队列与并发限额、运行审计（谁、何时、跑了什么、结果如何）
4. 统计看板（访问/实验/任务完成，手写 SVG，不引图表库）

**平台底座**
1. 账号：注册/登录/会话（cookie + 服务端会话表）、口令 PBKDF2（盐 + 迭代）
2. 协议：HTTP 路由表 + JSON API + SSE 事件流（实验日志）
3. 存储：SQLite（用户/会话/任务/记录/审计）＋ 文件系统（资源）
4. 运行沙箱：**固定命令表**（客户端只能选 id，带不了命令/参数/路径——沿用 lab.py 边界）、
   进程管理、超时与整树杀、日志环

## 五、架构（分层）

```
web（原生 HTML/CSS/JS，零构建）
  │  HTTP + SSE
HTTP 服务（标准库 ThreadingHTTPServer + 自研路由表）
  │
领域层（auth / courses / labs / tasks / admin —— 判定唯一源）
  │
存储（SQLite + 文件）
  │
运行时（子进程管理器：固定命令表、日志环、tree-kill、限额）
```

**协议先写**：`docs/protocol.md`（路由表 + 请求/响应约定 + SSE 事件格式 + 错误码）在 M2 动工前冻结 v1。

## 六、技术选型与边界

- 默认：**Python 3.12 标准库**（零下载、零构建）＋ SQLite ＋ 原生前端；
  与课设仓库十轮建成的工程文化一致（自研协议/对拍/证据链）。
- 备选：若学校偏好主流栈，领域层与协议文档可平移到 Spring Boot 3.3.5（本机缓存已具备）+ 同款前端；
  换栈不影响里程碑与验收。
- 部署：单进程可跑（`run.bat` 或 `python server.py`）；默认只绑回环，
  局域网/公网暴露需要显式开关（边界同 lab.py 的纪律）。
- 数据：所有课程/项目元数据**现算自仓库**（manifest/README 是唯一出处），平台 DB 只存平台自身状态。

## 七、里程碑（每轮交付可运行闭环 + 证据；功能点编号 F1-F18 见 DESIGN §三）

- **M0 · 方案书 + 可运行骨架（已完成）**：本方案书、服务骨架（`/health`、`/api/courses` 现算、
  静态托管、`/repo/` 内容源代理、`--selftest`）、占位首页（真的列出 33 个项目）。
- **M1 · 账号与会话（已完成）**：注册/登录/登出、PBKDF2(120k) 口令、服务端会话表（HttpOnly Cookie、
  12h）、学生/教师/管理员角色、失败限流（10 分钟 5 次 → 429）、同源基线（跨源 POST 403）；
  前端登录/注册页 + 会话感知顶栏；自测覆盖 26 项（含重复用户名/弱口令/错误口令/限流/登出失效/
  跨源/越权 can() 等负面）。
- **M2 · 课程目录与项目页（已完成）**：33 门课程目录（搜索 + 批次筛选）、课程工作区
  （一句话/知识点表/练习任务/踩坑/资料，全部现算自仓库）、项目页三页签（详情 / 在线演示 iframe /
  在线实验说明）；接口与页面测试进自检。
- **M3 · 在线实验（杀手锏）**：任务队列 + 并发限额 + SSE 实时日志 + 审计；
  固定命令表（跑演示/测试/启服务）+ 超时/树杀；负面：无权限/越权项目/超并发。
- **M4 · 练习任务闭环**：G2 卡片平台化：领取/完成记录/教师布置/进度统计。
- **M5 · 管理端 + 统计看板**：课程/用户/审计/看板（手写 SVG）。
- **M6 · 部署与论文素材**：一键部署、备份、压测与安全边界报告、
  需求/设计/测试/部署四章的论文素材整理。

## 八、验收与证据文化（沿用课设仓库十轮的规矩）

- 每个里程碑：`--selftest` + 真实端到端（两个客户端）+ 负面用例必须红在该红的原因上；
- 文档里的数字现算，口径进检查器；`run.bat` 两次退出码 0；
- 提交信息写清"做了什么、怎么验的、边界在哪"；本目录文档与代码保持可 GBK 控制台直读。

## 九、明确不做（这一版说"不"的事）

- 不做即时通讯/音视频/白板（参照项目是**规模标尺**，不是功能清单）；
- 不引入云服务/付费组件/前端框架构建链；不接 CI；不复制第二套业务判定源。
