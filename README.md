### 本轮（2026-09-30）B11 的做法

同样先探针、再修、再把每条失败钉成回归测试。网络代码的坑集中在"看起来跑通了"：

- **`STATUS` 表漏了 503**，构造响应时抛异常把事件循环线程带走，而线程异常被咽掉——
  表现只是"客户端等不到响应"，像超时又像死锁。现在 `stop()` 会把循环线程的异常抛回主线程。
- **Windows 上带着未读数据 `close()` 是 RST**，会把刚发出的 413/503 一起作废。
  拒绝与提前失败统一改成"发完承诺 → `shutdown(SHUT_WR)` → 读到对端 EOF 才回收"。
- **仿真信道自己骗了自己两次**：队列只看队头，晚到的头包堵住后面，`reorder` 参数形同虚设；
  两只插头接在同一方向，仿真里一个包都收不到而真套接字一切正常。
  现在有一条"必须真能倒过来交付"的测试专门盯着信道本身。
- 资源回收不能用"进程里 socket 对象数"当指标（客户端关闭是异步被发现的，结果随时序变），
  改成看服务端自己的账，并要求被拒/超时的连接让客户端读到 EOF。

`run.bat` 实跑退出码 0，运行前后目录快照无新增文件；与标准库的分歧（我们拒、它收）写成断言钉住，
哪天标准库默认变了，测试会先叫，而不是 README 悄悄过期。

### 本轮（2026-09-30）B12 的做法

五个范式各一个代表算法，每个都配一份"把定义直接翻译成代码"的参照实现，答案对不上就是错。
三条值得长期记住的教训：

- **对拍抓到的第一颗虫子不是算法错，是约定错**：Dijkstra 与 Floyd 把边表当无向、
  Bellman-Ford 当有向，200 组随机图里 118 组不一致——三个实现各解释一遍"图"，
  比的就不是算法而是约定。现在方向性由调用方用 `undirected()` 显式表达。
- **最坏界需要最坏输入才现形**：Bellman-Ford 在随机稀疏图上实测斜率只有 1.20，
  因为一轮没改进就提前收敛；换成"链式图 + 边倒序"才跑出 1.96（理论 V·E）。
  所以计时表必须写清输入是怎么造的，否则"实测比理论快"是幻觉。
- **期望值也要有出处**：本轮两次测试失败都是我自己算错——背包最优其实是 11，
  我编的比值贪心反例恰好等于最优解（换成 CLRS 的用例才成立）。
  "我以为的答案"不能当断言，要么现场算一遍，要么让参照实现给。

另外：输入生成不能算进耗时（实测虚高约 44%，绝对数字全灌水）；
演示用的东西错了等于没演示——N 皇后棋盘曾经把解打印成转置，算法对但展示不对。

### 本轮（2026-09-30）B13 的做法

编译原理这一轮的目标是"整条链能追踪"，所以每个阶段都单独可测，报错必须指到行列：

- **类型名有两套写法就能制造全线假错误**：语法给出 `int`，表达式类型内部用 `INT`，
  检查器一比较，16 个正常程序全被报"类型不符"，还连锁导致槽位没分配。修法是入口统一、
  AST 保留用户写的那个词，内部大写只在比较处用。
- **`1 == 1.0 == True`**：常量池用 `list.count(1)` 数会数出 3 个，去重也必须按 `(类型, 值)` 判等。
  Python 的这几个"顺手写法"在实现语言时全是坑。
- **VM 不能把内部错误外包给 Python**：越界常量索引原本抛 `IndexError`、坏运算码抛 `KeyError`，
  都不带我们自己的行号。现在栈下溢、槽位越界、跳转越界、非法运算码一律是带行号的自有错误。
- **两条后端对拍**（字节码 VM vs 树遍历）跑 300 个随机程序、399 处短路陷阱。
  生成器自己也会写错：第一版陷阱 `(g+10)/(g+10)` 在 `g == -10` 时合法地除零，
  错的是语料不是实现——**陷阱表达式本身也要被验证**。
- 一条不变式是"写错的测试"帮我确认的：漏跑 `analyze()` 时代码生成直接拒绝工作。

### 本轮（2026-09-30）B31 的做法

B31 的硬约束是**复用 B11 的 HTTP 子集，不写第二套解析器**。桥接只做一件事：把

- **复用第一次暴露了 B11 的真实缺口**：`STATUS` 表里没有 3xx，而 `Server._reply` 不给应用传 `reason`

- **校验必须在拆分之前做**：Python 3.10 起的 `urlsplit` 会悄悄吃掉首尾空白和 C0 控制字符。

- **名字空间是共享的**：别名 `1` 和自增 id 编出来的 `1` 是同一个键。把 409 抛给一个"根本没挑过短码"

### 本轮（2026-10-01）B21 的做法

上一轮证明"核对器会失败"，这一轮回答 QA 的另外两问：**什么算不合格**、**红了先做什么**。
所有口径都写成文档里的**规范表**，由导出器变成 `contracts/gate.json`，代码只执行不发明。

- **口径过期就拒判**。门禁执行器第一步先核对 `gate.json` 是否还是文档的现算结果；

- **兜底不是一个类别名，是一个结构约束**：它必须排在最后且**不带任何触发串**。

### 本轮（2026-10-01）B20 的做法

这一轮考的不是"再多写几个测试"，而是**验证机制自己会不会悄悄失效**。

- **每条核对器都要能被证明会红**：`tools/mutation_check.py` 登记 12 条变异（改模型不重生成契约、

### 本轮（2026-10-01）B19 的做法

SOA 这一轮的唯一考点是：**多一种接口，会不会顺便长出第二套判定**。
先量环境再定形态——`~/.m2` 里没有 Spring WS、SAAJ、JAX-WS、gRPC，
但 JDK 自带 `java.xml`，于是 SOAP 信封手写，**一个字节都没下载**（PLAN 第 8 节要求下载先同意）。

- **一份规则是被测出来的，不是被声明的**：`SoapInterfaceTest` 拿同一批数据、同一组身份，
  断言 REST 与 SOAP 的**可见集合、按钮、错误码逐字相同**。我往 SOAP 层塞了一条自造规则
  （维修员不看公共池），它立刻精确报出 `expected [R002, R003, R004] but was [R002, R004]`。
- **错误码跨协议要同字**：REST 用状态码、SOAP 用 Fault，各说各话就变成两套错误处理。
  做法是把业务码放进 SOAP 1.2 的 `Fault/Subcode`，并提供剥 QName 前缀的读回函数，比较才是逐字的。
- **状态字面量白名单**（`docs/10` 第 3 节）= Java 版的"判定源唯一"：
  只有 3 个文件允许出现 `"SUBMITTED"` 这类状态常量，扫描**先剥注释**再双向核对
  （我在这个文件自己的注释里写过反例，不剥就会误报——假阳性会让人去改注释而不是改代码）。
- **最有价值的一条缺陷**：照抄来的 XML 加固里 `disallow-doctype-declaration` 是 Xerces 专有特性名，
  JDK 解析器不认，于是**XXE 防护从未生效**，只是"拒绝一切"看起来像"防护到位"。
  教训进了 PLAN 第 6 节：**安全/加固配置必须有一条正向测试**。
- 本轮真缺陷 5 处全是我自己的（含"测试与实现各写一遍解析导致测试红实现绿"、"管道吃掉退出码"重犯），
  逐条记在 `docs/10` 第 6 节。
