## 数据来源声明

合成销售明细由 `clean.py` 按固定种子生成（AI 构造，非真实数据）：
40 个订单、6 种商品、**半数订单植入 P01+P02 配对**、其余随机；
再按已知数量注入五类缺陷（重复 3 / 未知商品 2 / 非法数量 2 /
金额缺失 3 / 负金额 1）。植入配对比例 1/2 是探针实测：1/3 经清洗
丢行后支持度只剩 0.26，够不着 0.3 的挖掘阈值。

## 实现时踩到的坑

1. **缺陷注入的顺序与重叠**：先追加重复行、后注入缺陷，缺陷可能抽中
   重复副本（与其源行同缺陷同被清理），清洗账本对不上；缺陷必须打在
   互不重叠的基础行上，重复行**最后**追加。
2. **"total" 的口径**：报表 total 是"进入清洗的行数"（含重复行 72），
   不是"注入缺陷前的行数"（69）——测试第一版把两个口径混成一个断言。
   守恒式应写成：total = clean + 四类剔除之和（填补不算剔除）。
3. **空簇很难自然触发**：初始中心取互异的数据点时，第一轮天然不空
   （初始中心距离自身为 0），Lloyd 迭代也很难清空一个小数据里的簇。
   探针跑了三种配置 900 个 seed 都没触发——测试改为断言该分支保护的
   用户可见不变式（结果簇覆盖 0..k-1），计数器保留作可观测性。
4. **关联规则里 lift<1 才是完整的课**：手算用例故意选了 conf=2/3、
   lift=8/9 的负相关规则——置信度高不代表有关系，提升度才是判据。

## 测试策略（28 项 = 19 核心 + 9 展示页；28 项测试双入口同数）

- Apriori：25 轮随机（3~6 商品、8~30 事务、三档支持度）与全穷举逐项
  一致；向下闭包断言；确定性；手算规则（conf 2/3、lift 8/9）
- K-means：团块对齐 100%、k=1 惯性=总方差、k=2 < k=1 惯性、60 seed
  确定性 + 簇覆盖完整、全同点 + k>1 拒绝、k=1 惯性 0
- 轮廓系数：1D 四点手算、单点簇 0、单簇 0、分离团 > 重叠团
- 清洗：注入账本逐数对账、行数守恒、清洗后复检（无重复/未知/非法/负值）
- 端到端：清洗 → 购物篮 → 挖掘，植入配对以规则形式重现（conf ≥ 0.6、
  lift > 1），且与穷举对拍一致

## 已知局限

- Apriori 逐个扫描事务计数（一次遍历计数全部候选）；无 hash-tree /
  FP-growth 等进阶结构。
- K-means 初始化为种子化随机取点（非 k-means++），小数据上够用；
  轮廓系数 O(n²)。
- 清洗规则针对本项目注入的五类缺陷；真实数据的清洗清单只会更长。
- 合成数据的关联规则结论不外推真实零售场景。

## 练习建议

1. 实现 FP-growth（无候选生成），并与 Apriori 在同一数据上比
   候选数/扫描次数。
2. 把 K-means 初始化换成 k-means++，在多峰数据上对比 100 个 seed 的
   惯性分布（箱线图）。
3. 给 Apriori 加事务 ID 列表（TID 集合）传递，避免每轮全表扫描。
4. 清洗链增加"金额按单价重算校验"步骤，统计账面金额与重算不一致的行。
