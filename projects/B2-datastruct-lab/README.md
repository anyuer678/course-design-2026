# B2-datastruct-lab —— 数据结构实验台：八个 ADT + 复杂度对照 + 交互菜单（数据结构）

**课程映射**：数据结构（PLAN 批次 1）；B12 的算法、B33 的可视化将复用本库的结构（PLAN 已登记）。

一句话：**"复杂度"不是标签，是数出来的**——顺序表插头部"搬"了多少步、链表查找"跳"了多少次、
线性建堆比逐个插入省了多少比较、路径压缩让 find 步数从多少降到多少，全部由代码里
的计数器**实测**，演示和测试用的是同一个口径。

**范围声明**：顺序表 / 单链表 / 栈（+括号匹配、中缀→后缀→求值）/ 循环队列与链式队列 /
二叉搜索树 / 哈希（链地址 + 线性探测墓碑）/ 二叉堆（含线性建堆、堆排序）/ 并查集（路径压缩+按秩）/
图（邻接表 + 邻接矩阵、BFS/DFS/连通分量），外加**交互菜单**（原始交付形态）。
**不做**（PLAN §4 选做项）：AVL/红黑树/B 树、KMP、哈夫曼、最短路/MST/拓扑/AOE、八大排序统计。

**复用决定（写明白）**：B1 有 `mini::vector` 等同款容器，但**本项目不复用**——
"顺序表/链表"本身就是本课的交付物，拿别人的容器当底座就等于不做题；反过来 B12/B33 复用
本项目（PLAN §4 已写"复用 B2 的结构而不重复造库"）。测试脚手架 `ds/check.hpp` 与 B1 同款，
各自项目自带（40 行计数宏，避免为一个宏建立跨项目构建依赖）。

## 知识点 ↔ 实现 ↔ 怎么被验证

| 课程知识点 | 代码 | 验证方式 |
|---|---|---|
| 顺序表的"搬元素"代价 | `SeqList::insert/erase` + `moves()` | 小样例**手算**到每一步（3 个元素头插 = 3 步）；300 次头插实测 44850 步（n(n-1)/2） |
| 链表的"跳指针"代价 | `LinkedList::find/at` + `hops()` | 手算（找第 3 个 = 跳 2 步、比较 3 次）；同题对照：头插只改链 300 次 |
| 栈的应用 | `brackets_match` / `infix_to_postfix` / `eval_postfix` | 括号 8 例手算；`3*(4+5)-6` → 后缀 → 21；括号不配对/非法字符/除零**必须抛错** |
| 循环队列的空/满 | `ArrayQueue`（size 记账） | 容量 4 的 head/tail 全手推（满时 head==tail==0 的"相遇"）；随机操作 vs `std::queue` |
| BST 删除三情形 | `BST::erase` | 叶/单子/双子（后继顶替）逐情形手推中序；随机操作 vs `std::set` |
| BST 的有序性 | `in_order` | 每次随机操作后"中序 == set 的升序迭代"逐元素对拍 |
| BST 退化 | `height()` | 升序 31 个 → 高 31；同一集合折半插入 → 高 5（实测对照） |
| 哈希冲突两策略 | `HashChaining` / `HashLinear` | 同余键扎堆：各查 12 次探测 78/78；分散键 12 次；**删除后墓碑不切断链**有专项用例 |
| 哈希查找 vs std | 两者 | 随机插入/删除/查找 vs `std::unordered_set`，另加周期性全键扫描 |
| 堆序不变量 | `Heap::verify()` | 每次 push/pop 后整树父子检查（对拍引擎里每步都做）；vs `std::priority_queue` 顶序对拍 |
| 线性建堆 O(n) | `Heap::build` | 降序 255 个：建堆 494 次比较 vs 逐个插入 1538 次（最坏情形逼出来） |
| 并查集 | `UnionFind` | 随机图连通分量/逐对连通性 vs **BFS**（两套独立算法对拍）；路径压缩前后步数实测 |
| 图的两种存法 | `Graph` / `MatrixGraph` | 同一随机图：邻接表 BFS 与矩阵 BFS 逐点一致；再 vs **反复松弛**（独立参照） |
| 遍历的代价口径 | `scans()` | 连通分量上 BFS 恰好扫 2E 条弧（手算图对账） |
| 菜单交互 | `run_menu(istream&, ostream&)` | **脚本驱动测试**：一整段菜单操作喂 `istringstream`，断言输出与退出码 |

## 重建时踩到的坑（都留了钉子）

1. **`in_order` 是"追加"语义**：我的测试复用一个 `SeqList` 收遍历结果，忘了清空——
   第一轮失败（size 越积越多）暴露出来。语义写进注释，测试里每个用例显式 `clear()`。
2. **手算计数也会错**：删头部 5 个元素的一批"搬动"我手数成 3 步，实际 4 步——
   忘了尾巴上的元素也要挪。教训同仓库记过的：**失败先怀疑自己的期望值**。
3. **中缀转后缀按位读会拆散多位数**：`10+2` 第一版产出 `1 0 2 +`（字面量被拆成两个词），
   求值也就会算错。改成"连续数字当一个整数词"后 `10 2 +` = 12。
4. **空桶查找不比较键**：`probes()` 对空桶不加计数是我实现的口径（看了 0 个键）——
   测试最初期望"任何一次查找都涨计数"，改成"非空链查找涨、空桶不涨"，把口径钉死在断言里。
5. **随机数据的堆对拍看不出建堆优势**：随机序列下逐个插入平均只上浮 ~1 层，
   比较数与线性建堆接近（实测 208 vs 206）——演示改用**降序**数据逼出最坏情形（494 vs 1538）。
   这条修正过程本身是"复杂度要对数据形状说话"的教材。
