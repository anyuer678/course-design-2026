# B37-industry-ai —— 设备故障预测：复用 B35 遥测 + B23 模型，做误报/漏报分析（行业软件 + AI）

**课程映射**：行业软件前沿应用 + 大型行业软件创新实践（PLAN 批次 7）。

一句话：**预测性维护不是"训一个模型"**，是把"要提前多久报警、误报和漏报各罚多少、
阈值按什么口径选"写成可对账的清单——本项目把 B35 的传感器遥测账本、B23 的手写模型
接进一条"特征 → 概率分数 → 阈值 → 告警"的流水线，并给出能追溯到**每一条误报**的解剖表。

**复用声明（本仓库纪律，也是本项目最该读的一段）**：
- `mqttlite.sensors.ReadingPlan`（B35）——异常分类学（spike/freeze/dropout）、概率容器、
  账本口径（逐类计数、sent 对账）与读数 schema 全部沿用；
- `mqttlite.svgplot`（B35）——告警预算曲线与设备时间线两张 SVG 是它的输出；
- `ml.tree`（B23）——决策树原样 import（测试断言 `isinstance` 证明没有第二份实现）；
- `ml.data.standardize / train_test_split`（B23）——防泄漏标准化与随机切分对照臂。

**但 B35 的 `SensorSimulator` 信号层没有整包复用——原因是实测不是喜好**：
它是无均值回复的随机游走，且 spike 是**持久偏移**（+40°C 留在游走状态里）。
480 步 × 3% 尖峰下温度被顶到 150°C 上限：实测 10 台设备均值 **141.3°C、18.3%
读数夹在 150**（同参数去掉尖峰则是 66.9°C、0 夹取）——短时演示没问题，长时线故障
预测里这个温度通道就失效了。B37 改用 **OU 均值回复基线 + 单点离群尖峰**，
这个测量本身由测试钉住（`test_b35_simulator_saturates_on_long_runs`）。

**范围声明与局限（必读）**：全部数据为**模拟**（合成遥测 + 注入故障 + B35 账本），
此处一切指标只说明流水线与评估口径自洽，**不外推为真实产线的预测效果**。
不做（PLAN 选做/等批准）：与 sklearn 库模型对拍（需安装，未批准）；真实数据接入。

## 运行

```
run.bat                                   # 三步：36 项测试 → demo（生成 build\ 下 3 张 SVG）→ 展示页新鲜度
python -m unittest discover -s tests      # 36 项（27 核心 + 9 展示页）
python tests/test_fault.py                # 直跑 27 项核心
python demo.py                            # 六段演示（唯一实时测量是第 3 段耗时列）
python tools\showcase.py --write          # 重生展示页 web\showcase.html（--check 过期即红）
python tools/logdiff.py a.log b.log       # 两次日志规范化比对（规则两类，会打印计数）
```

零依赖：纯标准库 + 复用 B35/B23 两个目录（`fault/__init__.py` 会把它们挂进
`sys.path`，缺目录时报一句人话）；`build\` 里的 SVG 双击即开、不联网。

## 知识点 · 实现 · 怎么被验证

| 课程知识点 | 代码 | 验证方式 |
|---|---|---|
| 预测性维护的口径 | `window_label`（horizon=24、排除暂态窗） | 逐边界断言：f-t=24 正、25 负、t≥f 起排除、f+W+decay 后回归负样本 |
| 特征不泄漏未来 | `window_features` 只用窗口内读数 | 把某窗口之后的所有读数改掉，该窗口特征**逐位不变**（且更晚的窗口确实变了） |
| 概率分数与阈值 | 手写逻辑回归（sigmoid + 交叉熵） | 解析梯度 vs 数值梯度（实测 2.8e-11）；GD vs Newton 最大权差 1.9e-3（L2 下的唯一最优） |
| 复用不抄第二份 | `ml.tree.DecisionTree` / `ml.data` | `isinstance` 断言 + 跨项目路径存在性断言；模型改动测试特征后权重分毫不动 |
| 误报/漏报权衡 | `sweep` / `roc_points` / `auc` | 阈值降 => 召回与报警数单调不降（断言）；打乱标签 AUC 跌回随机（10 种子实测 [0.33, 0.56]） |
| 数据质量 ≠ 设备故障 | `fp_context` + B35 账本 | 固定阈值 20/20 条误报**全部**发生在含 spike/freeze 的窗口（可追溯到读数行） |
| 提前量的定义 | `lead_times` | 只认 [f-horizon, f-1] 内首次报警；手算用例 + 全车队 6 个故障逐个钉值 |
| 切分口径 | `split_by_device` vs B23 `train_test_split` | 两臂都跑、数字都报；解释为什么部署口径必须按设备 |
| 静态可视化 | `report.py`（复用 B35） | 两遍构建**字节相同**；设备时间线的红圈数 == 该设备故障数 |

## 实测（2026-10-02，首次交付；数字均为本轮现算）

- **36 项测试（27 核心 + 9 展示页）**（`discover` 36 = 直跑 27 + 展示页 9）；`run.bat` **两次退出码 0**、
  `build/` 外无新增（产物 = alert_budget.svg 3066 字节、dev08_temp.svg 7750、
  dev08_vib.svg 7751）、两次日志经 `tools/logdiff.py` 规范化后**逐字相同**
  （各 69 行；规范项 = 单测计时 1 + 耗时列 3，两侧计数对称；2026-10-03 展示层批次⑧后按三步重测）。
- 展示页（2026-10-03 展示层工程批次⑧）：`web/showcase.html` 单文件自包含——六段演示原文
  （第 3 段耗时列脱敏成 <当场>）、**三模型对比表 + 阈值敏感性表**（结构化，来自现场输出）、
  **三张 SVG 内联**（alert_budget/dev08_temp/dev08_vib，同一份产物）；与现算**逐字一致**
  （`--check` 过期即红）。展示页测试 9 项（`python tests\test_showcase.py`）。
- 数据账：10 台 × 480 步 = 4800 条读数；故障 30 次（overheat 10 / wear 20）；
  异常账本 spike 147 / freeze 142 / dropout 0，逐类与行数对账相等。
- 样本账：724 窗口（排除 66 个故障后暂态窗）；训练 580（正 96）、测试 144（正 24）；
  按设备切分：训练 0..7、测试 8/9。
- 三模型对比（测试设备，best-F1 运营点）：**固定阈值**（100°C / 2.0）报警 29 条，
  P 0.310 R 0.375 F1 0.340；**B23 决策树** P 0.950 R 0.792 F1 0.864 AUC 0.899；
  **手写逻辑回归** P 1.000 R 0.750 F1 0.857 AUC 0.926。GD vs Newton 权差 1.91e-3。
- 阈值敏感性：best-F1 点 0.50（18 条报警）；召回≥95% 要到 0.02（111 条报警，P 0.207）；
  **告警预算 ≤24 条**时运营点为 0.22（P 0.833 R 0.833）——AUC 0.926 与选点是两个问题。
- 误报解剖：固定阈值 20 条误报**全部**（20/20）发生在含 spike/freeze 的窗口——
  阈值报警先被数据质量治理，再谈模型。
- 提前量：树在运营点 6/6 接住全部测试故障，提前 **16–19 步**（上限 horizon=24）；
  按类型 overheat 1/1、wear 5/5。
- 切分口径对照：按设备切 AUC 0.926 / 0.899；随机切分 0.848 / 0.868——
  本数据上两口径接近（特征全是设备无关统计量），但部署遇到的是新设备，口径仍按设备。
- 耗时（第 3 段【实测】列，跨运行有波动）：规则 0.4 ms；树 ≈1.0 s；逻辑回归 ≈0.8 s
  （纯标准库；树的成本主要在小样本上的阈值穷举）。

## 坑（都留了钉子）

1. **"能整包复用"是错觉，复用的边界是实测出来的**：B35 `SensorSimulator` 480 步
   温度均值 141.3°C、18.3% 夹取——它不是坏了，是为短时演示设计的（无均值回复 +
   spike 持久偏移）。只复用它合适的那几层（分类学/账本/schema/图），并在测试里把
   这个"不适用"的事实钉住，防止未来有人把 OU 当"重复实现"又合并回去。
2. **仿真里"加在哪一层"会被量出来**：第一版把尖峰 `temp += delta` 加在**游走状态**上，
   指数衰减尾巴（时间常数 20 步）让每台设备温度平均漂高约 25°C（101 vs 基线 76）——
   单点离群必须只进输出、不进状态。教训：仿真器每个字段的更新位置都是有语义的。
3. **无惩罚 logistic 的 MLE 在可分开方向上发散**：第一版没加 L2，GD 与 Newton 的权重
   差到 21.9（各自落在发散路径的不同点，"互拍"根本无从谈起）。加 L2=0.01 后差 1.9e-3。
   先有唯一最优，双实现互拍才有意义。
4. **logdiff 要连补位空格一起规范化**：耗时列 `{ms:>10.1f}` 在 766 与 1040 两种量级下
   位数不同，只替换数字会把"补位空格数"的差异留成假差异——规则改成连前置空格一起吃掉。
5. **GBK 控制台扫净（B4 同款教训复发）**：一堆数学记号（蕴含/等价/偏导/转置/上标等）让 `python demo.py`
   直接在 GBK 控制台崩（UnicodeEncodeError）；已对全源码做非 GBK 字符扫描并替换
   （16 处），这条每次动手写中文注释都得再扫一遍。

## 练习建议（G2，自己动手）

1. 把 `horizon` 从 24 改成 6 与 48 各跑一遍：提前量分布与召回怎么变？说清"要提前多久"
   是业务给的，不是模型选的。
2. 给随机切分臂换 3 个种子、给按设备切分换测试设备对（如 (4,5)），观察 AUC 波动——
   体会"单一切分的偶然性"（B23 练习第 1 条同款）。
3. 把 `spike_delta` 调到 10（尖峰不再越过 100°C），固定阈值基线的误报解剖会怎么变？
   解释"阈值选在哪"和"数据里有什么"是同一个问题的两面。
4. 给树加一个特征"距上次标定的步数"（或把 `temp_mean` 换成"相对本设备基线的偏差"），
   重跑按设备切分——想想为什么**去基线化**的特征才可能跨设备泛化。
