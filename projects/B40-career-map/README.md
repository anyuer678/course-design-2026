# B40-career-map —— 专业技能差距矩阵：证据可核验 + JD 映射器（专业实习）

**课程映射**：专业实习（PLAN 批次 8 / 毕业出口）。

一句话：自称"熟悉 XX"没法核验，但**"哪一行 README、哪个提交、哪句实测数字"可以**——
本项目把 B1–B39 的全部作品编成 **31 条可机验的证据**（指针=仓库路径、`@提交号`、
锚点字符串逐字比对），再做一台 **JD 映射器**：把你的目标岗位 JD 放进 `jd/`，
一键出"命中技能 → 已有证据 / 缺口 → 下一步练习"的差距矩阵。

**边界（先读）**：
- **不替你选岗位/方向**（PLAN §5）——映射什么由你放进来的 JD 决定；
  仓库里只有一个**显式标注「示例（非真实岗位）」**的合成 JD 用于演示。
- **不替代真实工作场景**：团队协作与业务上下文要靠实际参与——工具只做映射与核验。
- 缺口是诚实输出不是失败：`容器与云原生`、`消息队列与中间件` 两个技能面
  **故意留空证据**（仓库确实没有），映射命中时直接标缺口 + 给练习路径。

## 用法（三步）

```
1. 把你真实的目标岗位 JD 存成 jd/岗位名.txt（1–3 个即可，别改 EXAMPLE 文件）
2. python tools/map_jd.py --write        # 差距矩阵写到 build/jd_matrix.md（默认只打 stdout）
3. python tools/check_evidence.py        # 证据条目随时复核——改坏一条必须红
```

```
run.bat                                   # 三步：28 项测试 → demo（四段；无计时输出）→ 展示页新鲜度
python -m unittest discover -s tests      # 28 项（20 核心 + 8 展示页）
python tests/test_career.py               # 直跑同 20 项（本文件）
python demo.py                            # 核验 → 负面对照 → 示例 JD 映射 → 使用与边界
python tools/logdiff.py a.log b.log       # 两次日志规范化比对（规则只剩 unittest 计时）
python tools/showcase.py --write          # 重生展示页 web/showcase.html（--check 过期即红）
```

零依赖：纯标准库 + git（核验 `@提交号` 用；缺 git 时核验器明确报"无法核验"）。

## 知识点 与 实现 与 怎么被验证

| 课程知识点 | 代码 | 验证方式 |
|---|---|---|
| 声明必须可核验 | `check_evidence` 三层检查 | 31 条真实证据全过；假路径/假锚点/假提交三条负面对照各必须红 |
| 没有装饰条目 | 交叉引用检查 | 每条证据**必须被至少一个技能引用**（测试钉住；B22 台账同款规矩） |
| 匹配口径显式化 | `hit()`：英文词边界 / 中文子串 | `go` 不被 `gold` 命中、`spring boot` 短语命中、中文子串命中断言 |
| 缺口是诚实输出 | 空 evidence = 缺口 + practice | `test_gap_row_contains_practice`；真实缺口集合 {containers, message-queue} 钉住 |
| 示例必须可辨认 | 文件名 `EXAMPLE*` → 横幅 | `collect_jds` 的 example 标志 + 矩阵含「示例（非真实岗位）」断言 |
| 不替用户决定 | 无 JD 时退出并给指引；演示只跑示例 | `collect_jds` 空目录用例；README/矩阵页脚双重声明 |

## 实测（2026-10-02，首次交付；数字均为本轮现算）

- **28 项测试**（`discover` 28 = 20 核心 + 8 展示页；两文件直跑 20 / 8 分别 OK）；`run.bat` **两次退出码 0**、
  **无任何新增文件**、两次日志经 `tools/logdiff.py` 规范化后**逐字相同**
  （各 102 行；规范项只有 unittest 计时 1 条）。
- 核验器：**31 条证据、15 个技能面**，指针/提交/锚点全部通过；三条负面对照全红。
- 示例 JD 映射：命中 13/15 个技能面（C++、编译原理未提及，不计入矩阵）、
  **缺口 2 条**（容器与云原生、消息队列与中间件——仓库如实没有证据）。
- 证据覆盖：B1–B14、dorm-repair（B15–B22）、B23–B35、B37–B39 共 31 条，
  每条都能落到"某文件某句 + 某提交"。
- 展示页（2026-10-03 展示层批次⑩）：`web/showcase.html` = 示例 JD 差距矩阵成 HTML 表
  + 15 技能面全景（缺口行红标）+ 演示原文，与重算逐字一致（`--check` 过期即红）。

## 坑（都留了钉子）

1. **JSON 里别写半角引号**：`skills.json` 第一次写进 `"复制"` 这类半角引号直接 JSON 解析失败
   （两处）——中文注释/文案统一用「」；校验（`json.load`）已进每轮流程。
2. **锚点要"防平凡"**：`36` 这种短数字哪都能命中，等于没检查——锚点全部升级为
   "N 项 + 上下文"短语（如 `自测（36 项）`），逐条 grep 验证过才写进索引。
3. **一个假象要提前掐掉**："所有技能都有证据"会让缺口功能变摆设——所以
   containers/message-queue 两个技能面**故意保持空证据**（这也是实话），
   并在测试里把缺口集合钉死，防止将来被"顺手补满"。

## 明确不做（本期范围外）

替你选岗位/就业方向（PLAN §5）；自动抓取招聘网站（涉及抓取合规与账号，不做）；
简历生成器；面试题库。**本工具是"证据台账 + 映射器"，不是求职服务。**

## 练习建议（G2，自己动手）

1. 用 B39 的模板把一次技术主题复盘写成记录（问题/原理/证据/局限），
   证据指针指到本索引里的条目——两条工具链就接上了。
2. 给 `skills.json` 加一个你目标岗位特有的技能面（比如嵌入式 RTOS），
   **先想好每条 evidence 指针怎么被核验**再填——填不出来就是缺口，正好排期。
3. 把 `map_jd.py` 的英文匹配从"词边界"升级为"词边界 + 常见变体"
   （如 `k8s`/`kubernetes` 互相归一），先补测试口径再改实现。
