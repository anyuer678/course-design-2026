# B38 案例分析：Redis 的设计要点与我们实现的子集（软件工程案例分析与实践）

> 本文件是**先写的**（ROADMAP §3.8 的要求）：先把案例读明白、把子集与偏离写清楚，
> 再动手实现——实现的每一条语义都能在这份文档里找到出处或"简化声明"。

## 1. 为什么 Redis 快：单线程事件循环不是妥协，是设计中心

- **数据在内存里**：单次操作的成本是"内存访问 + 一次系统调用级网络往返量级"，
  瓶颈不在 CPU 也不在锁竞争，而在网络与序列化。
- **单线程串行化**：所有命令在一条事件循环里顺序执行，天然获得**原子性**——
  不需要给每个数据结构配锁（对比多线程内存数据库的锁粒度困境）。
  INCR 不是"先读再写"，而是"一串永不被打断的读-改-写"。
- **I/O 多路复用**（Linux epoll / 我们用的 Python `selectors`）：
  单线程同时盯着成百上千个连接，只在有数据时才工作——避免"一连接一线程"的
  上下文切换与内存开销。
- **代价与边界**：单条命令的耗时就是全体的延迟（大 key 操作会卡所有人）——
  所以 Redis 才有一堆"别做慢命令"的规范（SCAN 而非 KEYS、限制 value 大小等）。

## 2. RESP：一个"看得懂"的协议

RESP2 用**类型前缀 + 行**的极简结构，人 telnet 上去也能对话：

| 类型 | 编码 | 例子 |
|---|---|---|
| 简单字符串 | `+` 后跟正文 | `+OK\r\n` |
| 错误 | `-` 后跟正文 | `-ERR unknown command 'foo'\r\n` |
| 整数 | `:` 后跟十进制 | `:42\r\n` |
| 批量字符串 | `$长度\r\n` + 原字节 + `\r\n`；`$-1` 表示 nil | `$3\r\nbar\r\n` |
| 数组 | `*个数\r\n` + 各元素；`*-1` 表示 nil 数组 | `*2\r\n$3\r\nGET\r\n$1\r\nk\r\n` |

设计要点：
- **二进制安全**：长度显式给出，value 里可以有 `\r\n`、`\0` 任意的字节；
- **人类可读**：类型前缀一眼可辨，调试期 telnet 手写命令即可；
- **流式解析**：网络会**粘包/拆包**（一次 read 可能拿到半条命令、也可能一个
  包里三条命令）——解析器必须是"累积缓冲 + 尽力切帧"的状态机，
  不能假设"一次收包 = 一条命令"。这是本项目解析器与 fuzz 的重点。

另外 RESP 支持 **内联命令**（inline）：直接一行 `PING\r\n` 也能工作——
telnet 玩家的便利通道，解析时按空白分词（我们实现简化的双引号分段）。

## 3. 过期：为什么既要"惰性"又要"主动"

键到期不该再可见，但 Redis 不维护"到期定时器队列"，而是两条腿走路：

1. **惰性删除**：访问一个键时检查是否过期，过期就当它不存在（顺便删掉）。
   保证"到期的键**一定**不会被读到"。
2. **主动采样**：只靠惰性的话，**没人访问的过期键会一直占内存**。
   定期从"带过期时间的键"里**随机采样**一小批（Redis 默认每 100ms 一轮、
   每轮 20 个），删掉其中已过期的；若过期比例超过 25%，就再来一轮——
   用几十个样本的概率推断整库情况（**采样代替全扫**，不阻塞事件循环）。

为什么不给每个键配一个定时器？——百万键 × 定时器的内存与调度开销，
在单线程模型里会直接卡住主循环。**用少量随机采样换取"过期键占内存有上限"**
是这个设计的精髓，也是本项目要实测的：不访问也能被清掉（看主动计数）。

## 4. 内存编码（概念，本项目不实现）

Redis 会在运行时给同一种逻辑类型换"物理编码"：小整数直接嵌在指针里
（shared integers / intset）、短字符串用 embstr、集合小的时候用紧凑数组、
大了才转哈希表；还有**渐进式 rehash**（搬迁分批做，不卡事件循环）。
共同思想：**逻辑语义与物理表示分离**——上层命令语义不变，
底层为内存和缓存局部性做专门优化。

## 5. 持久化：RDB 与 AOF 的取舍（概念 + 我们的简化版）

- **RDB（快照）**：某一时刻的全量二进制镜像。加载快、文件小；
  两次快照之间的写入会丢。适合备份/灾恢。
- **AOF（追加日志）**：每条写命令追加到日志，可配置刷盘频率；丢得少，
  但文件大、恢复慢，需要重写压缩。
- 真实系统常两者兼用。本项目实现**简化快照**：头部版本魔数 + 条目数 +
  （键、值、绝对到期时刻）+ 校验和，**原子写**（临时文件 + `os.replace`），
  加载时校验版本与校验和；坏文件报一句人话而不是带病启动。

## 6. 本项目实现子集（命令语义表）

| 命令 | 语义 | 边界（测试逐条钉住） |
|---|---|---|
| `PING [msg]` | 无参回 `+PONG`；带参回 `$msg` | 参数超过 1 个 → 参数错误 |
| `SET key value` | 覆盖写，**清除该键的过期时间** | 键/值任意二进制；参数不齐 → 参数错误 |
| `GET key` | 取值；不存在/已过期 → `$-1` | 过期键被读到必须表现为"不存在" |
| `DEL key...` | 删除并返回删除个数 | 不存在的键不计入 |
| `EXPIRE key n` | 设过期 n 秒；**n≤0 立即删除**；返回 1/0（键不存在=0） | 重复 EXPIRE 覆盖旧时间 |
| `TTL key` | 剩余秒（向下取整，≥0）；-1=无过期；-2=不存在/已过期 | 到期边界：deadline≤now 即已过期 |
| `INCR key` | 原子自增；不存在按 0 起；返回新值 | **严格整数文法**（禁前导零/空白/小数点）；溢出 `2^63-1` → 溢出错误文本 |

**简化/偏离声明**（与真实 Redis 的差异，避免误当"兼容实现"）：
1. 只有字符串一种类型（无 LIST/HASH/ZSET）；无 `SETEX/GETSET/SETNX` 等多态变体；
2. `TTL` 用**向下取整**（真实 Redis 四舍五入到最近秒）——本实现口径写死在语义表里；
3. 内联命令只支持空白分词 + 双引号分段（真实 Redis 还支持转义等）；
4. 无多数据库（SELECT）、无事务（MULTI/EXEC）、无发布订阅、无复制/集群；
5. 快照是我们自定的简化格式（不是真的 RDB 文件），版本/校验和齐但无兼容性承诺；
6. 过期时间是**墙钟时间**（为了能落盘存活重启），测试用可注入的假时钟；
7. 长度上限：批量值 64MB / 数组元素 1M / 内联行 64KB（真实 Redis 是 512MB / 1M / 64KB，
   内存预算不同而已；超限返回协议错误并断开）。

## 7. 对拍策略（没有真 Redis 可对比时，怎么证明自己）

本机与 WSL 均无 redis-server（已实测，不装）——按 ROADMAP §3.8 的三条腿：

1. **协议层：第二个解析器交叉读**。写一个**独立实现**（不同风格：直接的
   下标推进 vs 主解析器的缓冲状态机）作为参照，对同一批线字节逐帧对比；
   再用"把语料改坏一个字节"验证两器**都必须报错**（防"一个宽松一个严格
   恰好在好数据上碰巧一致"）。
2. **行为层：语义表**。把上表的每条边界写成断言（含错误文本精确匹配）；
   `test_semantics_table` 的期望值逐条来自本文档。
3. **协议 fuzz**：种子化随机字节流——解析器不崩（只允许"得到值"或
   "定义好的协议错误"）；服务器不崩（坏包得到协议化错误并断开该连接，
   其他连接与新连接不受影响）。

**这不是"实现了 Redis"**：它是一个把案例里的设计要点（单线程循环、RESP、
双策略过期、快照取舍）落到可跑、可测、可对拍的**教学子集**。
