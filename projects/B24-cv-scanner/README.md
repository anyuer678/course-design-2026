# B24-cv-scanner —— 文档扫描仪：边缘检测 → 透视变换 → 二值化（计算机视觉）

**课程映射**：计算机视觉（PLAN 批次 6，安装决策点①）。

一句话：**计算机视觉的期望值最容易凭感觉——所以本项目的参照全是"造出来的"**：
程序渲染一份文档、记下它的四角/文字掩码/暗像素占比，再按已知透视"拍成照片"；
此后检测误差、还原质量、二值化准确率全部对着真值算，像素级有出处。

**环境声明（决策点①的落实方式）**：本机**已装 opencv-python（cv2 4.13.0）+ numpy 2.4.6**
（2026-10-02 实测），因此**零下载、零安装**；ROADMAP 里"装 opencv"的建议没有产生任何新下载。

**范围声明**：文档边缘检测（Canny → 形态学闭 → 轮廓 → 四边形逼近 → 角点排序）、
透视变换拉正、Otsu vs 自适应二值化对照、**五类失败样例的拒识路径**（带不同原因）。
**不做**（PLAN 选做项）：OCR（tesseract 需另装另批）、人脸检测演示；不做颜色/多页/批量流水线。

## 运行

```
run.bat                                          # 两步：16 项测试 → 六段演示（并写 PNG 到 build\）
python -m unittest discover -s tests             # 16 项
python tests\test_cv.py                          # 同上（双入口同数）
python demo.py                                   # 六段演示；产物在 build\demo_*.png（可直接打开）
```

依赖只有 cv2 与 numpy（均已安装），**零新依赖**。

## 目录

| 路径 | 是什么 |
|---|---|
| `cvscan/synth.py` | 合成器：渲染顶视文档（含文字掩码真值）→ 按已知四角透视"拍照"；可制造低对比/阴影/过小等难度 |
| `cvscan/detect.py` | 检测：Canny → 闭运算 → 轮廓 → 四边形判定 → 角点排序；四类拒识原因 + 边缘密度防噪声 |
| `cvscan/rectify.py` | 四对点透视变换（getPerspectiveTransform + warpPerspective） |
| `cvscan/binarize.py` | Otsu 全局 vs 自适应局部；与真值掩码的一致率/IoU |
| `cvscan/pipeline.py` | `scan()`：检测→还原→二值化；角点误差与还原对账工具 |
| `cvscan/io.py` | PNG 读写（`imencode` + Python 落盘，绕开 cv2.imwrite 的中文路径坑） |
| `tests/test_cv.py` | 16 项测试（真值对账 / 拒识路径 / 排序 / 确定性 / 读写往返） |
| `demo.py` | 六段演示 + 产物 PNG（build/ 下） |

## 知识点 ↔ 实现 ↔ 怎么被验证

| 课程知识点 | 代码 | 验证方式 |
|---|---|---|
| 检测流水线各步的分工 | `find_quad_candidates` | 20 个种子全部检出，角点最大误差 ≤ 3px（实测最差 2.00） |
| 四边形判定 = 面积 + 顶点数 + 凸性 | 同上 | "文档太小"样例被拒（面积不达标）；正常样例候选数=1、面积比 ≈0.24 |
| 角点排序（TL/TR/BR/BL） | `order_points` | 手摆打乱的四点排对；检出结果的**结构关系**（上边两点 y 更小等）逐条断言 |
| 透视变换 8 参数求解 | `rectify.four_point_warp` | 还原图逐像素 vs 原始顶视图：MAD ≤ 15（实测最差 11.2） |
| 二值化两派 | `binarize.py` | 与真值掩码一致率 ≥ 0.95（实测最差 0.961）、IoU ≥ 0.75；Otsu 阈值落在纸/字之间 |
| **失败样例对照** | `detect_document` 的原因分支 | 五类样例全拒且**原因各不相同**：无边缘 / 边缘密度过高（噪声）/ 面积不达标 / 图像太小 / 空图 |
| 噪声假阳性防线 | 边缘密度检查 | 纯噪声 37% vs 真实场景 1.1%——差两个数量级，阈值 0.25 有大量余量 |
| 确定性 | 全程 `default_rng(seed)` | 同种子两遍：图像、角点、二值图 `array_equal` |
| 中文路径的 I/O | `cvscan/io.py` | PNG 往返 `array_equal`；缺文件抛 FileNotFoundError |

## 实测（2026-10-02，首次交付；数字均为本轮现算）

- 测试：**16 项全过、双入口同数**。容差全部按"40 种子全量探针的实测最差 + 余量"定：
  角点最大误差 0.51~2.00px、MAD 5.7~11.2、掩码一致率 0.961~0.999、IoU 0.791~0.997、
  Otsu 与自适应一致率 0.988~0.998。
- `run.bat` 连跑两次退出码 **0**、`build/` 之外无新增、两次日志差异只有 1 行 unittest 计时。
- 演示现算：检出 20/20 种子；示例角点误差 ≤ 0.82px、还原 MAD 6.00、掩码一致率 0.9982；
  Otsu 阈值 138；五类失败样例各自的原因打印在演示第 5 段。
- 产物：`build/demo_input.png`（728KB）、`demo_rectified.png`（244KB）、`demo_binary.png`（3KB）
  ——已肉眼核对：拉正后文字行水平、无镜像。

## 坑（都留了钉子）

1. **`cv2.imwrite` 对含中文的绝对路径静默失败**（返回 False、文件不出现；相对路径却没事）。
   demo 最初用的是绝对路径——画了半天图根本没落盘，run.bat 还"成功"。修法：
   `imencode + Python 写文件`（`cvscan/io.py`），并且**写后验证字节数**，让静默失败变成响的错误。
2. **纯噪声会被误检成"文档"**（假阳性）：噪声的 Canny 边经闭运算糊成一整块，
   `approxPolyDP` 竟把它压成四边形。修法：**边缘密度拒识**——实测真实场景 ~1.1%、
   纯噪声 ~37%，差两个数量级，阈值 0.25 余量充足；这条没有"看起来对"，是量出来的。
3. **低对比样例第一次没造对**：只压缩"纸与字"的对比没用——纸对桌面的外轮廓照样被
   Canny 抓住（检测"成功"了）。修法：**整个场景洗白**（纸 210 / 桌 205），才真正无边缘可达。
4. **容差不能拍脑袋**：5 个种子的探针给出 0.991 的一致率，40 个种子才露出 0.961 的最差值。
   教训与前几轮同款：**取样规模不够时，"实测"也是一种猜测**。
5. **测试自己写错了异常类型**：缺文件是 `FileNotFoundError`（OSError 家族），我写成了
   RuntimeError——又一次"失败先怀疑自己的期望值"。

## 明确不做（本期范围外）

OCR（需 tesseract，另批决策）；人脸检测（OpenCV 自带级联可零下载，作为演示留作业）；
多页/批量/彩色文档；去阴影的专门算法（温和阴影下本流水线仍可用，见 `TestRobustness`；
更强的阴影会在演示里如实拒识或误差变大——不做隐藏）。
