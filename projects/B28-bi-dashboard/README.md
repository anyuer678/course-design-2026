# B28-bi-dashboard —— 商务智能看板（数据分析与商务智能）

**课程映射**：数据分析与商务智能（PLAN 批次 6）。

一句话：**把"口径"当成一等交付物**。每个指标都用两条独立实现算一遍（SQL 与被交付
口径同写的纯 Python 参照），两条必须逐数相等；筛选只走占位符 + 字段白名单，
并且**反过来用 B32 的静态扫描器查自己**还有没有拼接点。

**三条红线（先说在前）**
1. 数据是固定种子**合成**的，共现结构为演示而植入 → 所有结论**不外推**到真实业务。
2. 只绑 `127.0.0.1`，内存库不落盘。
3. 看板是给人看的页面 → **浏览器里的观感与点击只能由你实跑判断**（见文末走查清单），
   本机策略禁止自动化驱动浏览器，我不代勾 → 本轮按 PLAN §6 记 **自动化部分完成**。

## 运行

```
run.bat                    # 七步：环境 → 测试(双入口 42) → 政策核对 → 六段演示 → 展示页新鲜度 → 本地服务
run.bat no-server          # 前六步照跑（含展示页新鲜度），只跳过启动服务
python -m unittest discover -s tests     # 42 项（34 核心 + 8 展示页）
python tests\test_b28.py                 # 34 项核心（直跑入口）
python demo.py                           # 六段演示，数字全部现算
python tools\showcase.py --write         # 重生展示页 web\showcase.html（--check 过期即红）
python -m bi.server --port 8010          # 手工起服务
```

纯标准库（`sqlite3` / `http.server` / `html` / `csv` / `random`）+ 复用 B26/B27/B32，
**零下载零安装**。

| 数据血缘（知识图谱复用） | `lineage.NODES/EDGES` → B27 分层 SVG | `problems()` 要求每个指标都能追到清洗步骤与数据源、无孤岛节点 |

## 与 PLAN / ROADMAP 的偏离（如实记）

1. **PLAN §4 的 B28 基础范围原文是 `pandas→SQLite→Streamlit`**。本机实测
   `pandas / matplotlib / plotly` 全部 **MISSING**（只有 numpy 2.4.6，且本项目没用），
   按 ROADMAP 决策点 ③ 的既定替代走 **SQLite + 手写 SVG + 标准库 http.server**。
   这不是"顺手换个技术栈"：交互筛选、下钻、口径展示这些**课程概念**都保留，
   丢掉的是 Streamlit 的组件生态与拖拽体验。想升级需先批准安装（约 150MB 依赖树）。
2. **B26 的销售数据被重新生成了**（B26 的账本只有 40 单、无日期/客户/状态维度，
   撑不起月度趋势与复购）。清洗链与 Apriori/KMeans **仍是直接调用 B26**，没写第二份。
3. **B27 的图谱语义被借用而非改写**：血缘页里节点副标题仍写"批次N"（那是 B27 的领域词），
   我传的是层级号。没有 fork 一份渲染器去改文案——复制就会有两份会各自烂掉的东西。
4. **依赖 B32**（`sec32.audit.sql_sites`）：B32 目前只完成了四组靶件与扫描器，
   它自己的测试还没补。借用的是那个纯函数，代价写在这里；
   如果哪天扫描器行为变了，B28 的 `sql_policy` 会先红，不会静默放行。

## 踩过的坑（本轮真实记录）

1. **cmd 的多行 `if ... ( ... )` 块**让这份 `run.bat` 每次执行**第一行**先打印
   `The process cannot access the file because it is being used by another process.`，
   而退出码照旧 0、正文照旧跑完。定位方式是"逐行截断 + 前缀对照跑"：短脚本（B30 那份）
   同样结构却不触发，所以只能二分。修法：脚本里不放多行分支，判断移到 `step6.py`。
   教训：**一条"看起来无害"的 stderr/首行噪声也可能是解析错位**，别用退出码把它洗白。
2. **`ThreadingHTTPServer` 每请求一条线程**：默认 `check_same_thread=True` 的连接
   第一次请求成功、第二次就 500。只发一个请求的自测永远看不见它 → 服务器测试必须打两次以上。
3. **`mismatches()` 写成 `row.get("equal", True)`**，而 `gmv` 恰好没有 `equal` 字段 →
   最重要的指标**从来没被对拍检查过**，还一直显示"干净"。改成"缺字段同样是红"，
   并补两条测试钉住（一条正向、一条把字段抹掉看它是否点名）。
4. **`2026-13` 这种形状合法的假月份**一路通过校验，最后返回空表 + 200；`?evil=1`
   未知参数被静默丢弃也是同一类。两者都改成 400 + 中文原因：**静默空表比报错危险**，
   因为看板上看不出错。
5. **`_is_month` 把连字符下标写成 5（应为 4）**，把 `2026-05` 判成非法值。
   校验代码自己也得被测，否则它就是"看起来严格、实际错"的那种严格。
6. **客户池只有 40 人 × 864 单 → 复购率恒等于 100%**，指标成了装饰。
   放大到 800 人池后才出现 41.7%。**指标先要"有话可说"，再谈口径**。
7. **行序受 `PYTHONHASHSEED` 影响**：篮子用集合去重后再落行，位置一变，
   后面 `rng.sample` 抽中的缺陷位置就跟着变 → 整份数据不再可复现。
   改成 `sorted()` 后使用，并加一条跨 `PYTHONHASHSEED=0/3` 的等值测试。
8. **SQL 扫描器报了真误报**：`params + list(extra_params)` 是**列表**拼接也被算成拼接点。
   处理方式不是关掉规则，而是把它登记进 `JUDGED` 并写明"误报（已定性）"——
   静态检查的价值是"把所有可疑形态摊开由人定性"，定性必须留下文字。
9. **`scan_refs.py` 的默认路径是"当前目录"**：在仓库根运行时会把仓库根当 `projects/`，
   于是扫到 0 个项目却打印"全部项目的硬性交付物齐全"——**0 扫描的假绿**。
   已按 `__file__` 定位扫描范围、扫到 0 个项目就退出 2 并打印范围。
   这条同时修正了我上一轮（B30 收尾）引用过的结论：那句"齐全"当时就是 vacuous 的，
   结论碰巧对，证据不成立。本轮修好后它如实报出 B28 缺 README、B32 缺 README+run.bat。

10. **复用别家的渲染器会把"别人的文案"一起搬过来**（2026-10-03 批次⑨ 抓出）：血缘页借 B27 的
    `render_html` 时，页尾"数据来源：data/courses.csv 与 data/prereqs.csv"是 B27 的默认说明——
    对 B28 是错误的归属（且该页由 `/lineage` 路由对外可见）。修法：把来源说明参数化
    （默认值不动，B27 输出逐字不变），lineage 传自己的说明；**复用边界要连文案一起核对**。

## 已知局限

- 合成数据 + 植入共现：规则与分群只证明"管线能挖出东西且两路一致"，不证明任何业务事实。
- 单进程内存 SQLite，无并发写、无持久化；重启即清空。
- 分位数取最近秩下取整、KMeans 的 k=3 与 seed=0 都是**人挑的参数**，不是数据选的。
- 浏览器渲染与点击交互**未验证**（策略禁止自动化驱动）：`say.py` 打印 7 步走查清单，
  需要你实跑勾选。
