# B31-shorturl —— 短链系统（Web 系统与技术）

把长地址变成 `http://127.0.0.1:8000/l/1`。**HTTP 层直接复用 B11 的 `netlab`**：
这一轮的课题是 Web 应用本身——状态码语义、重定向、输入校验、前后端各自守哪条线，
而不是再写一个 HTTP 解析器。PLAN 第 7 节里给 B31 的硬约束就是这条：**不写第二套 HTTP 库**。

一次完整链路：

```
POST /api/links {"url":"https://…"}   →  校验/规范化  →  取号并编成 base62  →  201 + Location
GET  /l/1                             →  查库          →  命中数 +1          →  302 + Location: 目标
GET  /api/links/1                     →  读命中数与时间戳
```

## 和 B11 的复用关系（以及为它补的一处）

桥接在 `b31/__init__.py`：把 `projects/B11-net-lab` 插进 `sys.path`，然后
`from netlab.http1 import Request` 直接用。**不复制一份 netlab**——复制就意味着两套可以各自烂掉的解析器。

复用时撞到一个真问题：B11 的 `STATUS` 表里没有 3xx，而 `Server._reply` 不给应用传 `reason` 的机会，
所以 `302` 会在**事件循环线程里抛 `ValueError`**，客户端那边的表现只是"等不到响应"，
排查方向会跑到超时和死锁上去。已给 B11 补上 `301/302/303/304/307/409/415/429`
（附加式改动，没碰边界语义），并加了一条回归测试断言这些码可构造、304 不带 `Content-Length`、
表外的码仍要求显式 `reason`。**补完重跑 B11 全部测试：91 项 + 62 subTest 通过**。

B31 只用 B11 已实现的子集：`GET/HEAD/POST`、只认 `Content-Length`、`chunked` 一律 501。

## 接口

| 方法与路径 | 语义 | 成功码 | 可能的失败码 |
|---|---|---|---|
| `GET /` | 原生前端页面 | 200 | 500（页面文件缺失） |
| `GET /app.js` `/style.css` `/favicon.ico` | 静态资源，白名单 + 目录包含检查 | 200 | 404 |
| `POST /api/links` | 建短链；体 `{"url":…,"alias":…}` | **201** + `Location: /api/links/<码>` | 400 校验失败 / 409 别名冲突 / 413 体过大 / 415 类型不对 / 503 容量到顶 |
| `GET /l/<码>` | **302** 跳转，并计一次命中；访客带来的查询串并进目标 | 302 | 400 码形状非法 / 404 码不存在 |
| `HEAD /l/<码>` | 同上但**不计数** | 302 | 404 |
| `GET /api/links?limit=N` | 最近链接 + 汇总 | 200 | 400（limit 不是整数） |
| `GET /api/links/<码>` | 单条统计 | 200 | 400 / 404 |
| `GET /api/stats` | 汇总 + 命中榜 + 上限 | 200 | — |
| 对已知路径用错方法 | 405 + `Allow`（B11 只对全局不支持的方法判 405，这里补上"路径存在、方法不对"） | — | 405 |

三个值得单独说的选择：

* **302 而不是 301**：301 会被浏览器永久缓存，目标一改就再也不经过服务器，命中数直接失真。
* **所有响应都带 `Cache-Control: no-store`**：跳转和统计被缓存住，计数就不是计数了。
* **应用层错误返回三元组，不 `raise HttpError`**：netlab 对协议错误会关连接；
  用户打错一个字符不该把整条 keep-alive 连接也赔进去（有测试专门盯这条）。

## 短码怎么来

`links.id` 自增 → base62 编码 → 短码；别名和用户挑的码与自动码**共用一个名字空间**，
所以取号时会跳过已被别名占用的码（否则用户建了别名 `1`，第二条自动链接就会拿到一个
它没挑过的 409）。

* 字母表 `[0-9A-Za-z]`，62 进制。不用 base64 是因为 `+` 在查询串里等于空格、`/` 撞路径分隔符。
* 代价：**区分大小写**（`Ab` 与 `ab` 是两条链接，SQLite 的 `BINARY` 排序天然如此），
  且 0/O、1/l 人眼易混。
* `decode_code()` 只接受规范形式（不允许前导零），否则 `00` 和 `0` 会解出同一个 id，主键就不唯一了。
* 短码可由 id 推出，因此**可枚举**——这是教学实现的明确局限，不是成就。

## 目标地址的关卡（每条都有出处）

| 规则 | 为什么 | 出处 |
|---|---|---|
| 只收 `http`/`https` | `javascript:`/`data:`/`file:`/`vbscript:` 不是"另一种网页"，是把内容当代码执行的通道 | OWASP 对开放重定向与 XSS 的告诫；RFC 3986 4.2 |

| 拆 URL 之前先做不可见字符检查 | Python 3.10 起的 `urlsplit` 会**悄悄吃掉**首尾空白和 C0 控制字符，先拆再查就会让 `" http://a/"` 和 `"http://a/"` 变成同一个目标而字节数不同 | stdlib 实测（已钉成测试） |
| 拒 `user:pass@` | 凭据藏在短链里是钓鱼的常见做法；标准库乐意拆出来但不judge | RFC 3986 3.2.1（已弃用） |
| 主机名不做百分号解码 | 这里解一次，代理/浏览器再解一次，就是"同一地址两种理解" | RFC 3986 6.2.2 / 请求走私的老问题 |
| 主机名按 RFC 1123 校验标签，非 ASCII 走 IDNA | 中文域名要变成 punycode 才能上线 | RFC 1123、RFC 5890 |
| IPv6 字面量补回方括号 | `urlsplit.hostname` 会把括号剥掉，不补就拼出坏 URL | stdlib 实测 |
| 路径/查询里拒 `< > " \` \| ^ { } [ ]` | RFC 3986 的"排除字符"必须先编码；它们同时也是 HTML 定界符 | RFC 3986 2.2 |
| 百分号转义必须完整，十六进制位统一大写 | 残缺转义（`%2`）不该猜；大写化是规范化建议 | RFC 3986 6.2.2.1 |
| 默认端口去掉、scheme/host 小写、空路径补 `/` | 同一个目标只留一种写法，`norm(norm(x)) == norm(x)` | RFC 3986 6.2.2/6.2.3 |

## 踩过的坑（本轮真实记录）

1. **`STATUS` 表少 3xx**：302 在事件循环线程里抛 `ValueError`，客户端只表现为"没响应"。
   线程里的异常必须能传回主线程（B11 已有这个机制），否则你会去查超时。
2. **SQLite 连接跨线程**：连接在主线程建、请求在事件循环线程处理，默认 `check_same_thread=True`
   直接炸。光关掉检查不够——`create()` 的 `BEGIN…COMMIT` 跨多条语句，两个线程交错就会互相提交/回滚，
   所以外面必须再有一把锁：数据库自带序列化，但它不知道哪几条语句属于同一个业务动作。
3. **别名和自动码共用名字空间**：先建别名 `1`，自增 id 走到 1 就撞了；
   把 409 抛给一个"根本没挑过短码"的请求是没道理的。改成取号时跳过已占用的码。
4. **`urlsplit` 在拆分那一刻就抛 `ValueError`**（`http://[::1/x` 方括号没闭合），
   不是等读 `hostname`/`port` 才抛。我的 `try` 一开始包晚了位置，非法输入因此变成 500 而不是 400。
   同一个道理：端口越界也是 `parts.port` 抛异常，必须翻译成 400。
5. **`re.match` 是前缀匹配**：主机名校验用它，`a-.com` 里 `-` 结尾的尾巴被"部分匹配"放过了。
   校验一律用 `fullmatch`。
6. **`rest = raw[raw.index(netloc)+len(netloc):]` 会切错**：`http://h/p` 的 netloc 是 `"h"`，
   而 `"h"` 先出现在协议名里。改成按 `len(scheme)+3+len(netloc)` 定位。
7. **我自己写的规则是错的**：`#片段里不能再有 ?` ——片段里合法地可以出现 `?`
   （`http://a/#d?e` 完全合规）。写校验规则时"我觉得不对"不等于"标准说不对"，得回去查。
8. **路由表解包写错**：路由项是 `((方法, 模式), 处理函数)`，写成 `for method, pattern in routes`
   会让 `pattern` 变成处理函数，`fnmatch` 报 `expected str, bytes or os.PathLike object, not method`
   ——又一个"500 而不是 404"。
9. **404→405 的升级不能无条件做**：`GET /l/<不存在的码>` 先被路径匹配到 405，
   于是"码不存在"被报成"GET 不支持"，把最关键的一句话报反了。规则是
   **只有当前方法不在 `Allow` 里**才升级。
10. **Host 头部没有端口**：客户端发 `Host: 127.0.0.1`，服务实际在 8000，
    照抄头部就生成一个打不开的短链。头部带端口就尊重它，没带就补真实监听端口。
11. **`echo` 前面的中文 `rem` 也会出事**：把一句提示拆成两行 `echo` 之外，这次是
    `chcp 65001` **之前**的中英文混排 `rem` 让 cmd 按字节偏移续读时错位，
    从一行中文中间开始执行，报 `'不想动浏览器）：run.bat' is not recognized`，
    而**退出码仍然是 0**。规矩改成：**第一个 `echo` 之前的每一行都保持纯 ASCII**
    （注释用英文写）。这条是"tail 最后几行 + 看第一行"抓到的，光核对退出码会放过。
12. **`HEAD` 的响应要用 `body_expected=False` 读**：`Content-Length` 描述的是"GET 会有多大"，
    按体去等就会把下一个响应的开头当体吃掉，帧就错位了（demo 里踩过，测试里也钉了一条）。

另有 **12 处是我的测试写法或期望值错了、代码是对的**：12 字符的短码是形状错误（应 400 不是 404）、
管线化里第二个请求是读统计（hits 应为 1 不是 2）、`../web/index.html` 落回目录内不算越界、
`innerHTML` 的字面断言匹配到了我自己写的注释、制表符归"控制字符"那一支、
`2**64` 超出 id 上限（参照实现不限范围）、`favicon.ico` 对应的文件其实叫 `favicon.svg`、
"应当放行"清单里塞了 `http://a_%20b/`（主机名含 `%` 本来就该拒）、`encode_request()` 根本没有
`port` 参数、自指环那条用例忘了把 `::1` 放进 `self_hosts`、`accept()` 助手默认"输出等于输入"
（IRI 规范化后就不等了）、MIME 断言写成等值却漏了 `; charset=utf-8` 后缀。
按 PLAN 第 6 节：**期望值必须先算或找出处**——这一轮 again 说明"测试红了"先怀疑谁，是有成本的。

## 已知局限（说清楚，不含糊）

* **单进程单线程 `select`**：一台机器上的教学服务，不做负载均衡，也不保证慢客户端不拖住事件循环。
* **短码可枚举**：`/l/1`、`/l/2` 连续。真要防遍历得用不可预测的码 + 限流。
* **没有鉴权**：任何人能建链接、看别人的链接统计；没有删除和改指向接口。
  cookie 会话与访问控制是 PLAN 里写明的**扩展项**，不进基础范围。
* **信任 `Host` 头部**来生成给人看的绝对短链（跳转本身不依赖它）；公网部署要换成配置里的规范域名。
* **没有限流**：只有请求体大小、URL 长度、链接总数三道上限；`429` 已备好但没人发。
* **没有过期时间**：链接永久有效，除非手动删库。
* **持久性只到"提交"**：`sqlite3` 默认同步策略下掉电仍可能丢最后一次提交；没做备份与 WAL 归档。
* **统计只有次数**：没有来源、UA、时间去重，也不区分爬虫；`last_visit` 是最后一次命中。
* **不接 HTTPS、不公网开放**：这是本机回环环境；PLAN 第 8 节要求真实远端部署另行确认。
* **前端无框架、无构建**：所以也没有 i18n、暗色模式、虚拟列表；列表一次取 20 条。
* **百分号一律拒**（在主机段）、`\` 也要编码：PHP 风格 `?a[]=1` 必须写成 `%5B%5D` 才收。
