B31-shorturl · 短链服务：从"一个字符串"到"浏览器被领到另一个站点"

复用 B11 的 HTTP/1.1 子集（没有第二套解析器）：base62 短码 + 目标地址关卡 + SQLite 仓储 + 原生前端。本页数字全部现算自 demo.py（六段）——监听端口、Date 头、 创建响应长度三处易变值已按规则规范化为占位（页面干净、规则可审计）。

测试81 项（73 核心 + 8 展示页自测）
短码从哪来自增 id → base62 竖式长除法对拍；id=372642325 → 'PDZI5'；MAX_ID 4611686018427387903 → '5UfZOVH2ZO3'（11 位）；前导零 / 字母表外字符 / 超长 三类形态拒收
目标地址关卡收下并规范化 6 条（大小写、默认端口、IDNA、%2F）；拒收 10 条 + 自指环 1 条（协议白名单 / CR-LF / 凭据 / 百分号主机 / 端口越界）
状态码语义12 条全对（201、400、400、400、415、201、409、302、404、400、405、404）
keep-alive 与管线化一条连接 30 次跳转命中 30；管线化 GET+HEAD 都是 302；HEAD 不计数
统计与影子模型120 步随机操作，SQLite（SQL 语句）与纯 Python 字典模型逐步一致；影子模型累计命中 75 == 数据库累计命中
浏览器交互页面观感与点击交互待你实跑（run.bat 第 5 步，我不代勾）——本页把服务器侧证据（字节/状态码/统计）摆全

六段演示（现算；点页签切换段落）

短码从哪来：自增 id → base62
  id=1                   '1'  （1 位，解回 1）
  id=9                   '9'  （1 位，解回 9）
  id=10                  'A'  （1 位，解回 10）
  id=61                  'z'  （1 位，解回 61）
  id=62                  '10'  （2 位，解回 62）
  id=372642325           'PDZI5'  （5 位，解回 372642325）
  id=4611686018427387903 '5UfZOVH2ZO3'  （11 位，解回 4611686018427387903）
  字母表                    0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz
  为什么不用 base64           `+` 在查询串里等于空格，`/` 撞路径分隔符
  拒绝 '00'                短码 '00' 有多余的前导零：不是规范形式
  拒绝 'a-b'               短码含字母表外的字符 '-'
  拒绝 'zzzzzzzzzzzz'      短码长度应在 1..11，收到 12
目标地址的关卡
  收下并规范化                 https://Example.COM/Path  →  https://example.com/Path
  收下并规范化                 http://a:80/x  →  http://a/x
  收下并规范化                 http://a/中文  →  http://a/%E4%B8%AD%E6%96%87
  收下并规范化                 http://例え.テスト/x  →  http://xn--r8jz45g.xn--zckzah/x
  收下并规范化                 http://[::1]:8080/p?q=1#f  →  http://[::1]:8080/p?q=1#f
  收下并规范化                 http://a/b%2fc  →  http://a/b%2Fc
  拒收                     'javascript:alert(1)'        协议 'javascript' 不在白名单 ('http', 'ht
  拒收                     'data:text/html,x'           协议 'data' 不在白名单 ('http', 'https') 
  拒收                     'file:///c:/win.ini'         协议 'file' 不在白名单 ('http', 'https') 
  拒收                     'http://user@a/'             目标不能带 user:pass@：把凭据藏进短链是钓鱼的常见做法
  拒收                     'http://a/ b'                第 10 个字符是空白：URL 里空格要写成 %20
  拒收                     'http://a/\r\nSet-Cookie: x' 第 10 个字符是 CR/LF：会被拼进响应头，拒收
  拒收                     'http://a/<b>'               路径/查询里第 2 个字符 '<' 是 RFC 3986 排除字符，
  拒收                     'http://a%2eb/'              主机名 'a%2eb' 含 %：主机段不做百分号解码。在这里解一次，
  拒收                     'http://a:99999/'            主机/端口无法解析：Port out of range 0-6553
  拒收                     'http://[::1/x'              无法拆分：Invalid IPv6 URL
  自指环也拒                  UrlError：目标指向本站 /l/ 路径
    现场示范                 目标指向本站自己的 /l/ 路径，会形成跳转环

怎么自己跑

  • run.bat：五步（环境 → 测试 → demo → 展示页新鲜度 → 启动服务）； run.bat no-server 跳过最后一步。
  • python demo.py：只看六段演示（临时目录建库，项目目录不留文件）。
  • python tools\showcase.py --write：重新生成本页；--check 重算比对、过期即红。

服务默认起在 127.0.0.1:8000（页面零外链，此地址只是运行说明）；页面样式、 手感与点击交互请自己起服务看。

生成物：python tools/showcase.py --write（口径见 showcase/SPEC.md； 仓库级校验 python showcase/check.py）。页面数据全部现算，无外部请求。
