[2/5] 应用路由：键值表的增删改查 + 查询串
========================================================================
  GET    /                          -> 200 'netlab 迷你 HTTP 服务器 / GET  /               本帮助 / GET  /kv…'
  PUT    /kv/name                   -> 201 'ok'
  PUT    /kv/city                   -> 201 'ok'
  GET    /kv                        -> 200 'city / name / repair'
  GET    /kv/name                   -> 200 'anyuer'
  POST   /kv/name                   -> 200 'updated'
  GET    /sum?a=1.5&b=27            -> 200 '28.5'
  GET    /echo?text=hello+world%21  -> 200 'hello world!'
  DELETE /kv/city                   -> 204 ''
  GET    /kv/city                   -> 404 'no such key'
  说明：204 没体所以不带 Content-Length；HEAD 带长度但不带体；405 会附 Allow；`..` 上跳在解析层就被拒。

[3/5] keep-alive、多路复用，以及每一种越界被拒的样子
========================================================================
  响应: HTTP/1.1 200 OK 体=b'netlab \xe8\xbf\xb7\xe4\xbd\xa0 HTTP \xe6\x9c\x8d\xe5\x8a\xa1\xe5\x99\xa8\r\nGET  /               \xe6\x9c\xac\xe5\xb8\xae\xe5\x8a\xa9'
  响应: HTTP/1.1 200 OK 体=b'name\nrepair\n'
  响应: HTTP/1.1 200 OK 体=b'{"requests": 15, "connections": 13, "peak_open": 1, "open_no'
  一条连接上跑了 3 个请求：连接数=13 请求数=15
  8 个客户端同时挂着时服务端同时持有 8 条连接，历史峰值 8（始终只有一条线程）

  越界请求的响应码：
    请求目标超长                       -> HTTP/1.1 414 URI Too Long
    头部条数超限                       -> HTTP/1.1 431 Request Header Fields Too Large
    裸 LF 换行                      -> HTTP/1.1 400 Bad Request
    chunked（不支持也不忽略）             -> HTTP/1.1 501 Not Implemented
    两个不一致的 Content-Length        -> HTTP/1.1 400 Bad Request
    声明巨体                         -> HTTP/1.1 413 Content Too Large
    不认识的版本                       -> HTTP/1.1 505 HTTP Version Not Supported
    路径上跳                         -> HTTP/1.1 400 Bad Request

  解析层直接抛出的错误（同一条规则在客户端也能挡住）：
    b'GET / HTTP/1.1\n\n'… -> 400 Bad Request: 请求头里出现裸 LF（必须用 CRLF 换行）
    b'POST / HTTP/1.1\r\nContent-Length: 1\r\nCo'… -> 400 Bad Request: 多个 Content-Length 取值不一致：['1', '2']
    b'GET /a/%2e%2e/b HTTP/1.1\r\n\r\n'… -> 400 Bad Request: 路径不允许 `..` 上跳
  目前统计：{'requests': 31, 'connections': 29, 'peak_open': 8, 'open_now': <当场>, 'timed_out': 0, 'refused': 0, 'errors': 9}

[4/5] UDP：有边界、没顺序、没可靠性
========================================================================
  发两次、收两次，边界原样保留：b'first-datagram' + b'second-datagram'
  没人发的时候 recv 只能等到超时返回 None：None  ← 包丢了还是对方根本没说？UDP 不区分，也不告诉你
