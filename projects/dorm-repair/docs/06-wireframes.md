# 06 · 线框与界面状态（B16）

> **这是什么**：文字线框 + 一个能真的点起来的原型（`prototype/`）。
> 没有 Figma、没有视觉稿，因为这个仓库的验收标准是"可核对"，而观感只能由人判断。
> 所以本文档负责两件机器能查的事：**每个界面元素回链到需求 ID**，
> 以及**四态（正常 / 加载 / 空 / 错误）在每个视图里怎么呈现**被写死成约定。
> 视觉层级、留白、配色好不好，见 `07-walkthrough.md` 的人工走查清单——我不会替你打勾。
>
> 元素 id 与 `prototype/web/index.html` 一致；`tests/test_prototype.py` 会核实这些落点存在。

## 通用约定

| 约定 | 做法 | 出处 |
|---|---|---|
| 状态呈现位置 | 每个功能区一个 `role="status"` 的即时反馈行（`#identity-state`、`#create-status`、`#load-state`、`#detail-status`），错误另用 `role="alert"` 区域 | US-01、NFR-03 |
| 语言 | 全站中文，`lang="zh-CN"`，UTF-8 | NFR-04 |
| 按钮文字 | 动词开头（"提交报修""接单""验收通过"），不写"确定/取消"这类无信息词 | UC-03、UC-04 |
| 规则来源 | 按钮有没有、点了要填什么，全部读服务端返回的 `attemptable` / `required_inputs` | 第 3、5 节；NFR-02 |
| 键盘 | 跳转链接 `.skip` → 每个 `h2` 可聚焦 → 表格"打开"按钮 → 详情标题获得焦点 → Esc 关闭详情 | 可访问性 |
| 时间显示 | 一律 `toLocaleString()/toLocaleTimeString()` 按本地格式，不显示原始秒值 | FR-15、IF-03 |

## V1 · 身份切换（顶部）

```
┌─ 宿舍报修 · 交互原型 ─────────────────────────────────────────┐
│ 这是 B16 的走查原型：身份由下面的切换器模拟，不是登录（B18）。│  ← #identity-note
├───────────────────────────────────────────────────────────────┤
│ 角色   [ 学生（报修人） ▼ ]   我是 [ stu-1 ▼ ]  [切换身份]    │  ← #role / #actor
│ 当前以 STUDENT 身份查看：stu-1                                │  ← #identity-state (status)
└───────────────────────────────────────────────────────────────┘
```

要点：**页面上明写"不是登录"**。身份切换只改变服务端用来判定的角色，不改变判定规则——
这正是 NFR-02 想让人在走查时亲眼看到的：换成学生去点派单，按钮根本不会出现，
硬发请求也会被服务端拒（`tests/test_prototype.py::test_server_refuses_actions_the_role_cannot_take`）。

| 元素 | 回链 |
|---|---|
| 角色下拉三项 | 第 1 节角色枚举、第 6 节可见性矩阵 |
| "我是"下拉 | `prototype/server.py` 的 `IDENTITIES`（模拟池，非账号系统） |
| 提示文案 | IF-01、01 节"认证属 B18" |

## V3 · 工单列表（三个角色共用一套版式）

```
┌ 3 · 工单 ──────────────────────────────────────────────────┐
│ 状态[全部▼] 分类[全部▼] 宿舍编号[        ] ☑ 只看逾期      │
│ [筛选] [清空]                                               │
│                                                            │
│ 正在加载工单…                          ← #load-state        │
│ ┌───┬────────┬────────┬──────────┬──────────┬────────┬─────────┬────┐
│ │编号│宿舍    │分类    │紧急/时限 │状态      │时限到期│描述     │操作│
│ ├───┼────────┼────────┼──────────┼──────────┼────────┼─────────┼────┤
│ │R003│B02-205 │FURNITURE│URGENT / 2h│[已逾期]  │…       │床架…    │打开│
│ └───┴────────┴────────┴──────────┴──────────┴────────┴─────────┴────┘
│   ↑ caption：可见范围由服务端的可见性矩阵决定，不由这里筛选
│
│ ┌ 空状态（虚线框）──────────────────────┐
│ │ 这个视图下暂时没有工单。               │
│ │ 空状态是设计的一部分：它必须说清        │
│ │ "是没有，还是没加载出来"。             │
│ └───────────────────────────────────────┘
│
│ ⚠ 加载失败：…　这不是"没有工单"，是请求没成功。  ← #error-state
└────────────────────────────────────────────────────────────┘
```

三条设计决定：

1. **空 ≠ 错**：请求失败时显示 `#error-state` 并明确写"这不是没有工单"，空状态只在服务端
   真的返回零条时出现（`empty` 字段）。把失败伪装成空，用户就永远不知道自己该重试。
2. **逾期排最前**：排序键 `(逾期优先, 编号)`，管理员一进列表先看到该急的。
   逾期判定用模型自己的时钟（原型是注入的假时钟，NFR-05），不是浏览器时间。
3. **列表不做权限判断**：收到的集合已经是服务端按可见性矩阵筛过的。前端若再自己 filter，
   就会出现"前端漏筛 → 越权可见"的经典事故（`test_filters_narrow_without_escaping_visibility`）。

| 元素 | 回链 |
|---|---|
| 可见集合 | 第 6 节可见性矩阵（FR-12、FR-13、FR-14） |
| 状态徽章 / 逾期徽章 | 第 1 节状态枚举、第 8 节逾期定义 |
| 筛选表单 | FR-14、AC-31、AC-32 |
| "打开"按钮 | 详情视图 V4 |

## V5 · 反馈与可访问性规范（跨视图）

* **每个会变化的区域只有一个反馈出口**：状态行（`role="status"`）用于进度与结果，
  警报区（`role="alert"`）用于错误。同一信息不同时出现在两处。
* **不靠颜色单独表意**：逾期除了描色还写"已逾期"三个字；错误除了描红还有文字与 `aria-invalid`。
* **焦点可见**：全局 `:focus-visible` 描边；打开详情把焦点送到详情标题（`tabindex="-1"`），
  关闭后不劫持焦点；Esc 关闭详情面板。
* **表格可被读屏理解**：`<caption>` 说明可见范围从哪来，表头 `scope="col"`，
  行内按钮有明确文字"打开"（不是图标）。
* **移动端不做假响应式**：窄屏隐藏"时限到期"列（信息在详情里仍可见），不是把表格横向压缩成一团。
