# 13 项目计划与范围（B22）

这一篇不管技术，管的是**这个项目的范围是怎么一步步定下来、又是怎么被现实改掉的**。
它最重要的约束只有一条：**这里的每个数字都是台账现算的**（写成 `L:键=值` 标记），
`checks/check_pm.py` 会重算并逐个比对——手抄的数字在管理文档里是有害的，
因为它过期时不会有任何东西变红。

## 1. 台账机制（本轮唯一的新"机制"）

| 角色 | 谁做 |
|---|---|
| 事实源 | PLAN §7 的轮次标题、`docs/05` 的待决问题表、`contracts/*.json`、`docs/12` 门禁表、`tools/mutation_check.py` 登记表、本 README 的坑编号列表 |
| 现算 | `python tools/project_ledger.py --dump` |
| 落盘 | `contracts/ledger.json`（`--write`），`--check` 比对 |
| 引用 | 管理文档写 `L:rounds_dorm=8` 这类标记 |
| 核对 | `checks/check_pm.py`（流水线 `pm` 层）——值不对、键不存在、台账过期，都算红 |

台账**不记录**运行期度量（测试条数、各层耗时）。那些是"某一次跑的结果"，
归 `docs/11`、`docs/12` 的实测表，并由流水线每次重测。把它们抄进台账只会再造一个需要人维护的副本，
而这正是本文件要消灭的东西。

## 2. 计划与实际

| 项 | 计划 | 实际 | 差在哪 |
|---|---|---|---|
| 批次 5 的做法 | 八轮迭代共用一套代码（B15–B22），但 PLAN 早期写法容易读成"八个小程序" | 明确成**一轮一个项目**，用户单句"继续"放行下一轮 | 不是范围变化，是**表述收敛**：把"八套四件套"改成"同一目录逐轮加东西" |
| 已完成轮次 | — | 全项目 `L:rounds_done=20` 轮有 G1 记录，其中报修业务 `L:rounds_dorm=8` 轮 | 批次 5（B15–B22）已收尾 |
| 日历跨度 | 每周 8–10 小时的假设 | 实测只落在 `L:rounds_dates=3` 个日期上 | **这条要老实说**：日期是我执行时的系统日期，不是按真实课表推进的里程碑；PLAN §8 自己记着"缺原始课表、可投入时间与最近截止日期"，这些只有你能给 |
| 交付验收 | G1（技术）+ G2（学习） | G1 每轮实跑；G2 一条都没勾 | G2 归你，我不代勾，也不替你认定学习效果 |

## 3. 范围：每轮"在范围内 / 明确不做 / 为什么"

这是七轮里做过的真实收窄。**"不做"分三种**，混在一起写就等于没写：
`决定不做`（价值判断）、`环境所限`（本机没有）、`延后`（下一轮或以后）。

| 轮次 | 在范围内 | 明确不做 | 类别与理由 | 出处 |
|---|---|---|---|---|
| B15 需求 | 可执行需求模型 + 三方核对 + 追踪矩阵 | 真实调研、UI、任何实现 | 决定不做：我没访谈过任何人，所以 12 条假设全部登记为待决问题 | `docs/01`、`docs/05` |
| B16 交互 | 线框、四态约定、可访问性、可点原型 | 认证、存储、并发、把业务规则复制进前端 | 决定不做 + 延后：判定源必须唯一；真实存储归 B18 | `docs/06`、ADR-02 |
| B17 体系结构 | 分层与依赖方向、3 份 ADR、机器可读契约 | 写任何 Java、拆服务 | 决定不做：那轮考的是结构，不是语言 | `docs/08`、`docs/adr` |
| B18 平台 | Spring Boot 分层单体 + H2 + 乐观锁 + REST + 跨语言对拍 | 真实认证、多实例、性能实验 | 延后（B21/B22 范围之外）+ 决定不做（没跑性能就不写性能结论） | `docs/09` |
| B19 双接口 | 查询用例的第二种形态（SOAP 1.2 + 契约生成 WSDL） | gRPC、WS-Security、写操作进 SOAP | **环境所限**：本机 `~/.m2` 没有 Spring WS / SAAJ / gRPC，下载需先获同意；写操作不进 SOAP 是范围决定 | `docs/10` 第 1、2 节 |
| B20 测试工程 | 反例收缩、后果量化、变异自检台、9 层流水线 | 接云端 CI、覆盖率百分比 | 决定不做 + 环境所限：CI 要联网与授权；本机没覆盖率工具，编一个数比没有更坏 | `docs/11` 第 5 节 |
| B21 质量保证 | 门禁口径 + 失败分诊 + 走查证据对齐 | 分支保护、CODEOWNERS、评审流程 | 决定不做：**这个仓库还没有一个 commit**，"合入"只能是本地一条命令的判定 | `docs/12` 第 5 节 |
| B22 项目管理 | 计划/风险/复盘三篇 + 台账与核对 | 新增功能、改实现、提交推送 | 决定不做：本轮的价值就在"把账算清"，加功能会把复盘变成宣传 | 本篇 |

## 4. 变更控制：口径怎么改才算数

这一套代码里的"改需求"不是嘴上说一句，它有固定路径（B18 裁决 AQ-02/03/12 时走的就是这条）：

1. 改文档里的**规范表**（SRS 的表、门禁表、分诊表）；
2. 重生成对应生成物（`traceability.csv`、`contracts/workflow.json`、`verdict_table.json`、`gate.json`、`ledger.json`）；
3. 让模型与实现跟着改，**两边逐格对拍**（`L:verdict_cells=1680` 格）；
4. 跑门禁：blocking 层全绿才算通过（当前 `L:gate_blocking=9` 层，共 `L:gate_layers=11` 层）；
5. 新增的断言必须先回答"它能被什么改动弄红"，答不出来就不写。

违反任何一步都会撞墙：改文档不重生成 → `contract`/`verdict`/`qa` 层红；
改实现不动文档 → `docs`/`arch` 层红；把关键层降成 advisory → 导出器直接拒绝。

| 界面是否好用 | 你 | `docs/07` 的 20 步结果列全部仍是『未验证』，`check_qa` 会拒绝代填 |

## 6. 下一轮（B23 起）之前要先补的信息

## 8. 指标一览（每个数字都是现算的，写错就红）

这张表是台账的**全部公开键**——`checks/check_pm.py` 要求每个键都在这里被引用一次：
没人读指标就别留那个键，这是台账防止自己变成装饰的方式。

| 键 | 值 | 从哪算出来 | 判读 |
|---|---|---|---|
| `rounds_done` | `L:rounds_done=20` | PLAN §7 的『已完成』标题 | 全项目有 G1 记录的轮次数 |
| `rounds_dorm` | `L:rounds_dorm=8` | 同上，限批次 5 | 同一套代码上连做的轮数（批次 5 已收尾） |
