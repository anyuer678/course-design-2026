# 12 质量保证：门禁口径与失败分诊（B21）

测试（B20）回答的是"对不对、能不能失败"；质量保证要回答另一个问题：
**不合格的东西有没有可能被放出去，放出去之后谁来拦、红了先做什么。**
所以本轮三件产物：一张**门禁表**（哪些层必须绿才放行）、一张**分诊表**（红了归哪类、下一步跑什么）、
以及把 `docs/07` 那 20 步人工走查与自动层**对齐**（哪些行已经有机器证据、哪些永远只能由你判断）。

一句话口径：**"全部通过"不是放行条件，"blocking 层全部通过并且读数取到了"才是。**

## 1. 门禁表（规范表，由 `tools/export_gate.py` 机器读取）

10 个层与 `tools/pipeline.py` 的层集合必须**完全相等**——多一层、少一层、名字打错都拒绝导出。
"拦不拦"只有两个取值：`blocking`（不绿就不放行）与 `advisory`（红了照样放行，但必须在报告里点名）。

| 层 id | 拦不拦 | 这层拦下的是 | 红了先做什么 |
|---|---|---|---|
| `docs` | blocking | 需求表、可执行模型、追踪矩阵三者说不同的话 | 先确认这次动的是需求还是实现；需求真变了就跑 `checks/check_docs.py --write` |
| `contract` | blocking | 契约落后于文档与模型，Java 会读旧表 | `python tools/export_contract.py --write`，然后看 Java 是否跟着变 |
| `verdict` | blocking | 跨语言判定基准过期，对拍失去参照 | `python tools/export_verdict_table.py --write`，再跑 Java 对拍 |
| `arch` | blocking | 依赖越界、Java 里长出第二份判定、ADR 缺节 | 不要改文档来迁就代码；先看那条边是不是违反了 ADR-02 |
| `pm` | blocking | 管理文档里的数字与台账现算不一致、风险登记册漏了未决项、复盘没覆盖全部坑——**本轮交付物就是文档 + 证据，数字过期就是交付物有错** | `python tools/project_ledger.py --write` 后重跑 `checks/check_pm.py`，看是哪一篇过期 |
| `qa` | blocking | 门禁口径过期、走查清单某步的证据是条不存在的测试、结果列被检查器代填 | `python tools/export_gate.py --write` 后重跑 `checks/check_qa.py` |
| `pytests` | blocking | 需求模型的行为回归（状态机、权限、可见性、时限） | 读失败消息里的期望值出处，判断是被改坏还是需求真变了 |
| `javatests` | blocking | 平台实现与契约/判定表分叉，或构建"0 个测试"假绿 | 先分清是 `Tests run=0`（工具链）还是某格分叉（实现） |
| `mutation` | blocking | 核对器失去牙齿——这轮的绿从此不可信 | 逐条跑 `tools/mutation_check.py --verbose`，看是哪条变异没弄红 |
| `shrink` | advisory | 最小反例收缩退化到非最短（调试工具变钝） | 产品未必坏，但反例不再可信；修完再升回 blocking 讨论 |
| `consequences` | advisory | AQ-10/AQ-11 的量化结果漂移（假设或模型变了） | 先看数字是否随参数假设改动；是就更新 `docs/11` 的实测表 |

**为什么 `mutation` 是 blocking**：它管的是"验证机制本身还可不可信"。
它红了还说"可以合"，等于把整套门禁变成装饰。
**为什么 `shrink` / `consequences` 是 advisory**：它们度量的是**工具与假设**，
不是产品行为；把它们设成 blocking 会让人养成"为了变绿而改工具"的习惯——那是门禁最坏的失效方式。

## 2. 分诊表（规范表，由 `tools/triage.py` 机器读取）

分诊输入是**层的失败输出文本**，规则**按顺序**取第一条命中；全都不命中就落进最后一类。
每个类别都必须至少有一条真实样本（样本就是 `tools/mutation_check.py` 的登记变异，
不另编"看起来像"的假日志），所以删掉一条规则会立刻有测试红。

| 类别 | 触发特征（输出里出现） | 含义 | 该跑什么来确认 |
|---|---|---|---|
| `artifact-stale` | `已过期`、`契约与模型不一致`、`判定表与当前模型不一致`、`与现算事实不一致`、`台账现算` | 生成物落后，重生成即可 | `--write` 后重跑该层 |
| `architecture-violation` | `依赖越界`、`疑似第二份状态表`、`ADR` | 结构约束被破 | `python checks/check_arch.py` 单跑，看是哪条边 |
| `doc-model-divergence` | `文档一致性检查发现`、`：文档`、`可见性矩阵` | 文档与模型说不同话 | 用需求来源列判断哪一侧才是新裁决 |
| `harness-broken` | `没能把对应核对器弄红`、`变异锚点命中`、`不可达` | 验证工具自己被削弱 | `python tools/mutation_check.py --verbose` |
| `toolchain` | `BUILD SUCCESS`、`Tests run=0`、`找不到 Maven` | 构建或环境，不代表产品坏了 | `python tools/java_build.py --require` |
| `register-incomplete` | `没有登记进风险登记册`、`没有被 docs/13 第 8 节引用`、`复盘漏了` | 该登记的没登记：风险、指标或复盘条目缺项 | `python checks/check_pm.py` 单跑，看缺哪一条 |
| `policy-tampering` | `被降级成 advisory`、`不在分诊表里` | 门禁口径本身被动过——最危险的一类，因为它让别的层从此没人拦 | `python tools/export_gate.py --check` 单跑，看是哪一行被改 |
| `behavior-regression` | （兜底，不命中以上任何特征） | 真实行为回归 | 读那条测试的期望值出处，判被改坏还是需求变了 |

`doc-model-divergence` **故意不猜"是谁改的"**：光看输出文本分不出"需求变了没同步"与"实现漂了"，
硬要分就是编故事。分诊器给类别 + 确认动作，人来判定归属；`git diff` 是最终裁判，但本轮不提交，
所以确认动作写成可独立执行的第二条命令。

## 3. 人工走查与自动层的对齐

`docs/07-walkthrough.md` 加了第 5 列**自动证据**：要么是 `T:文件::方法`（检查器会去源码里核实它在不在），
要么写 `只能人工`。**"你的结果"那一列仍然是给你填的，我不会代勾**（本轮实测：20 步里
有自动证据 N 步、只能人工 M 步——数字由 `tools/quality_gate.py` 现算并打印，不手抄）。
对齐的价值是把人的注意力留给机器测不到的东西：观感、键盘顺序、读屏念法、窄屏是否溢出。

## 4. 本轮的门禁怎么跑

```
python tools/quality_gate.py                 # 跑全部 9 层，按口径判定放行/拦下，并对每个红层给分诊
python tools/quality_gate.py --json          # 同一结论的机器可读版（给"CI"用的那份产物）
python tools/export_gate.py --check          # 门禁表/分诊表 ↔ contracts/gate.json 是否过期
run.bat gate                                 # 批处理入口：只跑门禁
```

## 5. 明确不做

* **没有分支保护、没有 CODEOWNERS、没有 code review 流程**：这仓库一个 commit 都没有（PLAN 第 8 节：
  提交与推送不是本轮授权），所以"合入"在这里是**本地一条命令的判定**，不是服务端强制。
  我把它写成"门禁"是因为它做的是门禁的判定动作，别当成流程已经落地。
* **不接云端 CI**（要联网与授权），没有并发、没有缓存、每次都要真跑 9 层。
* **不算覆盖率百分比**：本机没装覆盖率工具，编一个"覆盖率"数字比没有更坏。
  本轮可报的替代指标只有：验收标准里可执行入口的条数（`check_docs` 报）、
  每条分诊规则的真实样本数、走查 20 步里自动证据覆盖的步数。
* 不做静态扫描/依赖漏洞扫描（需要联网查库）。

## 7. 本轮踩过的坑（都是我自己的）

1. **分诊特征串凭记忆写，结果对不上真实输出**。我写的是 `文档一致性发现`，
   `check_docs` 实际打印的是 `文档一致性检查发现`——`--selftest` 当场报 **12/15**，
   三条 `doc-model-divergence` 样本全落进兜底类。教训与 B20 同源：**规则的触发条件必须由真实输出反推，
   不能由我回忆**；这也是为什么分诊表要求"每类都有真实样本"。
2. **兜底那格被切成一个伪特征串**。`strip_ticks` 原来按顿号/逗号分段后再过滤含"兜底"的段，
   于是"（兜底，不命中以上任何特征）"的后半句变成一个**真的模式**存进 `gate.json`——
   兜底规则带着模式，就不再是兜底。`tests/test_gate.py` 的分隔符测试把它抓了出来，
   现在改成"整格含兜底 ⇒ 空特征"。
3. **走查表加列时插错位置**。第一次脚本把证据并进了"期望"单元格（列索引算错），
   20 行全脏。靠 `check_docs.tables_in` 的列数校验现形（表头 5 列、行 4 列 = 立刻报），
   修法是重建行而不是继续 patch 行。
4. **`T:` 引用漏了 `test_` 前缀**：我从测试清单里抄名字时被 `sed` 把前缀吃掉了，
   12 条引用全指向不存在的方法。`check_qa` 一次报出 13 处问题。
   这条正好证明 B15 立的规矩有效：**引用一个不存在的测试比留空更坏**，而检查器会去源码里核实。
5. **prototype 变异一开始"红"在拷贝缺陷上**：临时副本里没有 B11 的 `netlab`，
   `server.py` 直接 `RuntimeError`，看起来像"核对器抓到了"，其实是自检台没把外部依赖带上。
   现在 `EXTERNAL_DEPS` 会把 netlab 拷进副本的同级位置，并在注释里写清这是拷贝不是链接。
6. **中文串里嵌英文引号又把脚本写崩**（`"结果列被检查器代填成"通过""`）——这个坑 B18/B19 记过，
   本轮在补丁脚本里第三次重犯。规则不变：字符串里别嵌裸引号，用『』或直接去掉。
7. **`triage.py` 忘了 `sys.path.insert`**：作为脚本运行时 `sys.path[0]` 是 `tools/`，
   `from tools import mutation_check` 直接 `ModuleNotFoundError`。
   `--text` 分支看不出来（它不需要导入），只有 `--selftest` 才走到——**新命令的每条分支都要真跑一次**。

### 探针清单（改坏哪里 → 什么变红）

| 破坏 | 变红的对象 |
|---|---|
| 改了门禁表（verdict 降 advisory）不重生成 `gate.json` | `qa` 层：`gate.json 与 docs/12 不一致` |
| 走查某步的证据写成不存在的测试 | `check_qa`：`第 6 步声称有自动证据，但 … 没有这个方法` |
| 把『你的结果』代填成『通过』 | `check_qa`：`检查器不许代填` |
| 删掉一行走查（20 → 19） | `check_qa` 与 `tests/test_gate.py::WalkthroughEvidence` 同时红 |
| 停掉『关键层不许降级』守卫 | `test_downgrade_attack_is_refused` |
| 停掉『兜底必须排最后』校验 | `test_sample_claiming_an_unknown_category_is_refused` |
| 停掉『规则不许没有触发串』校验 | `test_rule_without_pattern_can_never_hit` |
| 停掉『层集合必须相等』校验 | `test_missing_layer_is_refused` |
| 停掉走查结果列核对 | `test_checker_may_not_fill_the_users_column` |
| 停掉 `T:` 引用存在性核对 | `test_fake_test_reference_is_caught` |

两条**我自己指错对象**的探针也记在这里，因为"探针没红"有两种完全不同的原因：
一条是断言真的没牙齿，另一条是我打错了地方。
① 第一次用 `triage.py --text` 的失败分支去验"兜底排最后"——那条守卫由 `test_gate` 的另一条断言管；
② 用"停掉 `len(rows) != 20` 守卫"去验 `test_count_is_twenty…`——那条测试**自己直接数行**，
不依赖守卫，所以要改成"删一行走查"才看得出牙齿（结果 checker 和测试同时红）。
**分不清这两种情况，就会把"我没验准"记成"它没牙齿"。**

## 8. 与 B20 的分工

B20 回答"这些核对器会不会失效"，B21 回答"失效了算不算不合格、谁拦、红了先做什么"。
两者共用同一批真实样本：`tools/mutation_check.py` 的登记表既是 B20 的牙齿证明，
也是 B21 的分诊样本集——**没有为了本轮再造一批假日志**。
