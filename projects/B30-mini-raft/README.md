# B30-mini-raft —— mini-RPC、一致性哈希与 Raft 模拟（分布式与云计算）

**课程映射**：分布式与云计算（PLAN 批次 7）。

一句话：把 Raft 的两条安全性约束放进一个**能逐事件检查不变式**的模拟器里跑，
再用真套接字的 mini-RPC 把"TCP 上没有消息边界"这一课补上。

**红线（先说在前）**：这是**单进程事件驱动模拟**，不是一套多进程真集群；
没有快照、没有成员变更、没有日志压缩。**未做完不宣称完整 Raft**（PLAN 原文要求）。

## 运行

```
run.bat                    # 三步：unittest 发现 → 直跑测试文件 → 六段演示（约 1 秒）
python -m unittest discover -s tests -v
python tests/test_b30.py   # 双入口同数：15 项
python demo.py             # 六段演示，数字全部运行时现算
```

纯标准库（`socket` / `threading` / `heapq` / `bisect` / `random` / `json`），**零下载零安装**。

## 目录

| 路径 | 是什么 |
|---|---|
| `raft30/rpc.py` | mini-RPC：一行一条 JSON 的帧协议、`FrameDecoder` 累积解码、按 `id` 关联响应、每连接一线程的服务端 |
| `raft30/hashing.py` | 朴素取模分片 `NaiveShard` vs 一致性哈希环 `ConsistentHash`（带虚拟副本），加对比指标 `moved_fraction` |
| `raft30/sim.py` | Raft 模拟：选举（含"日志不落后才给票"）、日志复制、`§5.4.2` 的只提交本任期条目、分区与重启、三条不变式检查 |
| `tests/test_b30.py` | 15 项自测（参照出处写在文件头） |
| `demo.py` | 六段演示 |

## 知识点 ↔ 实现 ↔ 怎么被验证

| 知识点 | 落在哪里 | 怎么被验证（不是"跑过了"，是"能失败"） |
|---|---|---|
| TCP 没有消息边界 | `rpc.py` `FrameDecoder` | 两帧粘在一次到达解出 2 条、半帧停在边界（补完才出第 2 条）；坏帧（空行/非 JSON）被跳过且**不回包** |
| RPC 的响应关联 | `RpcClient.call` | 真套接字回声三类请求（含中文与嵌套 dict）；客户端按 `id` 匹配，允许乱序 |
| 哈希分片的代价 | `NaiveShard` vs `ConsistentHash` | 2000 个键实测：朴素取模 4→5 搬 **81.0%**（理论 ≈80%），一致性哈希搬 **23.9%**（理想 1/(n+1)=20%）；且"不属被摘节点却搬家的键 = 0 个" |
| 虚拟副本与均衡 | `ConsistentHash(vnodes=…)` | `vnodes=10` 时三节点负载 `{a:579, b:724, c:697}`（实测，不是断言"应该均匀"） |
| 确定性可复现 | `Simulation(seed)` | 同一 seed 的事件序列与结果逐次一致：`demo.py` 跑两遍输出**逐字相同** |
| Election Safety（一个任期至多一个 leader） | `on_request_vote` 的每任期一票 + 日志新旧比较 | `check_election_safety` 在随机事件流**每个事件后**跑；1800 次检查 0 失败 |
| Log Matching（论文原话） | `on_append` 的 `prev_term` 校验 + 冲突即截断后缀 | 同 index 同任期 ⇒ 前缀必须逐条一致；**注入同任期分叉必须被抓**（有专门一条测试钉住，防止断言被写松） |
| Leader Completeness / §5.4.2 | `_advance_commit` 只推进**本任期**条目 | 构造"旧 leader 被隔离在少数派、隔离期收 ghost，多数派选出新 leader 提交 real"，愈合后断言 **ghost 不在任何节点状态机里**、real 全员一致 |
| 状态机安全 | `applied_prefix()` | 比较的是**已应用前缀**而不是"当前值"——follower 落后是正常的，比当前值会把复制延迟误判成分歧 |
| 分区与丢包 | `Network.partitioned` | 分区期间丢弃计数（实测 299 次），多数派侧仍可提交、少数派侧不能 |
| 重启与持久化 | `Simulation.restart` | 持久字段（term/voted_for/log/sm/commit/applied）保留、易失字段清零；重启后重新选出 leader 且已应用前缀只前进 |

## 实测（2026-10-02，`run.bat` 连跑两次）

- 测试：**15 项通过**，双入口同数（`unittest discover` 与直跑文件都是 15）。
- `run.bat` 两次退出码均 **0**、日志 `not recognized` **0**、目录文件清单两次一致（19 个文件，**无新增**）。
- 两次日志的差异**只在耗时行**（本次 `diff` 出 1 行 `Ran 15 tests in 0.10x s`；上一次是 2 行）；
  **六段演示跑两遍输出逐字一致**（`diff` 0 行，60 行输出）。
- 目录快照两次一致要说清口径：`find` 出的 19 条里**含 `.ruff_cache/` 与 `__pycache__/*.pyc`**
  （我此前跑 ruff/pytest 留下的缓存，不是 `run.bat` 生成的）；`run.bat` 跑完**一条新文件都没加**。
- 演示读数（现算）：选举 `seed=0` 在 t=20 选出节点 2（term=1），三条命令后全员 `commit=3 / applied=3`；
  分区场景 `seed=1`（分裂当时旧 leader 节点 2 term=1、新 leader 节点 0 term=2）；
  随机事件流 10 seed × 60 步 = 600 个事件，**每个事件后**跑三条不变式 = **1800 次检查** 0 失败；
  期间 **30** 次选举、**299** 次分区丢包；
  重启场景 `seed=3` 重启前后 `(term, log, commit, sm) = (1, 2, 2, {a:1, b:2})` 完全保留，t=219 重新选出 leader。

## 与 PLAN / ROADMAP 的偏离（如实记）

1. **ROADMAP §3.4 写"多进程 + 重启/分区实验"**：这里做成了**单进程事件驱动模拟**
   （选举/复制/分区/重启都有）+ **一个真套接字的 mini-RPC**（`socket` + 每连接一线程）作为通信层实物。
   理由：模拟器的价值恰在"时间可控、每个事件后能查不变式、同 seed 可复现"，
   真多进程会把这些性质换成 flaky 测试。**没有**偷偷把"多进程"划掉——这条就是记录。
2. **事件时间线导出 HTML**（ROADMAP 的可视化项）**未做**：`sim.timeline` 目前是文本列表。
   没做的原因很简单：一旦交付 HTML，它就需要你在浏览器里实跑验收（本项目已有 B27 卡在这一步），
   我不拿"生成了但没人看过"的东西当完成。列为扩展项。

## 踩过的坑（本轮真实记录）

1. **不变式被写强了，不是实现有 bug**：`check_log_matching` 第一版要求"任意两节点日志的**公共前缀**逐条相同"。
   `demo.py` 第 5 段在 `seed=5` 当场抛 `节点1/4 在 index 1 任期不一致`。查现场：分区表为空、两节点 `commit=0`、
   index 1 分别是 term 1 与 term 2 —— 这是**合法中间态**：新 leader 还没用自己的条目去覆盖 follower 那条
   **未提交**的旧任期条目。按论文原话改成"同 index 同任期 ⇒ 该处及之前逐条相同"，
   并补三条测试：当年 seed 复跑不抛、合法中间态明确放行、**注入同任期分叉必须仍被抓**。
   教训：**断言写强和写松一样危险**——写松会漏，写强会把正确实现判成 bug，而人第一反应往往是去改实现。
2. **演示读数取错了时刻**：第 4 段最初打印"旧 leader term=2、新 leader term=2"，看起来像"同任期选出两个 leader"，
   其实是愈合后两边收敛了。改成在**分裂那一刻**取任期（1 与 2），并加一行解释为什么必须那时取。
3. **代码注释里留着一条更早的现场**（不是我踩的，是上一会话记在 `sim.py` 注释里的）：
   追加日志时按 0 基下标写 `log[-1]`，`prev_index=0` 的空日志直接 `IndexError`——
   Raft 实现的经典翻车点，本实现按 1 基下标处理并有复制测试兜着。
4. **交付前体检发现测试文件自身有三处问题**：未用的 `import socket`、未用的变量 `lid`、
   `wait_leader` 被定义了两次（后一次覆盖前一次）。都是 `ruff --select F,E9` 一眼能看到的，
   说明**接手别人写的项目也要重新体检**，不能假定"测试绿＝交付干净"。
5. **我这轮自己的两次小失手**：① 用 `python tests\test_b30.py` 在 Git Bash 里被吃掉反斜杠
   （报"找不到文件"，不是代码问题）；② 往测试文件追加内容时按 `unittest.main()` 做锚点，
   实际文件是 `unittest.main(verbosity=2)`，替换静默没生效——**先读再改**，别照记忆写锚点。

## 明确不做（不是"以后再说"，是本期范围外）

- 多进程真集群、真实网络乱序/重复投递、磁盘持久化与 WAL、快照与日志压缩、成员变更（Joint Consensus）。
- 写请求线性化（本章只保证状态机安全与已提交条目不被覆盖）。
- 选做：事件时间线导出 HTML（见上文偏离 2）。

## 已知局限

- 结论只在"这套 seed 与这套参数"上成立：`t=20` 当选、`81.0% / 23.9%` 等数字是**固定种子的实测值**，
  不是理论界，也不是性能测量（本模拟不测吞吐/延迟，也不该被拿去外推）。
- 分区模型是"组间静默丢弃"，没有拜占庭节点、没有消息篡改与重放。
- 状态机只有 `set`，没有条件写入/事务，因此不涉及一次安全性更强的提交论证。
