# B41-thesis-seeds —— 毕业设计种子：5 个候选的三维可行性（毕业设计/论文）

**课程映射**：毕业设计（论文）（PLAN 批次 8 / 毕业出口）。

一句话：**候选题清单不等于开题**——本项目把 ROADMAP 预列的 5 个候选题做成
"**数字会自己过期的比较文档**"：每条候选的数据/资源/评价三维都要有实测事实垫底
（关键文件行数、缺口探针如"fsync 计数=0"、环境探针如 sklearn 缺失），
`tools/check_seeds.py` 每次运行都**重算复核**——谁动了候选对应的代码，这里立刻红。
**选定哪一个是用户的决定，本工具只负责让比较有据可依。**

**五个候选（详见 `data/seeds.json` 与比较表）**：
1. **B10 加 fsync + 页式存储**（持久性工程化）
2. **B13 加函数调用帧与错误恢复**
3. **B30 Raft 完整化**（快照 + 成员变更）
4. **B38 主从复制**（RESP 内复制协议子集）
5. **B23 + NumPy/scikit-learn 对拍扩展到更大网络**（sklearn 属安装决策点，未批不装）

## 运行

```
run.bat                                   # 两步：16 项测试 → demo（四段；唯一实测=fsync 基准两行）
python -m unittest discover -s tests      # 16 项（双入口同数）
python tests/test_seeds.py                # 直跑同 16 项
python demo.py                            # 核验 → 负面对照 → 三维比较表 → fsync 基准【实测】
python tools/check_seeds.py               # 只跑事实核验（行数/探针/锚点，过期即红）
python tools/report_seeds.py --write      # 比较表写到 build/seeds.md
python tools/logdiff.py a.log b.log       # 两次日志规范化比对（基准 ms 行 + 单测计时）
```

零依赖：纯标准库（环境探针 numpy/sklearn 是**被测对象**不是依赖）。

## 知识点 ↔ 实现 ↔ 怎么被验证

| 课程知识点 | 代码 | 验证方式 |
|---|---|---|
| 可行性要有数字 | `seeds.json` 的 files/probes | 24 处文件行数、9 个探针全部现算复核（PASS 行打印计数） |
| 数字会过期 | 行数**逐字比对** | 改错一行 → RED（负面对照钉住）；动代码不改 JSON 也会红 |
| 缺口要有证明 | `code-count` 探针 | "B10 没有 fsync / B13 没有 CALL / B30 没有 snapshot / B38 没有 replica"——计数=0 且 glob 必须真匹配到文件 |
| 环境是决策点 | `import-check` 探针 | numpy 可导入 / sklearn 不可导入实跑判定；期望与现状不符即红 |
| 基准要标口径 | `bench_io.py` | 60 次中位数、8KB 记录、同目录——demo 打印 plain/fsync 两行【实测】 |
| 选定留给用户 | 报告页脚 | `test_report_footer_keeps_choice_with_user` 钉住"选定由你/不等于开题" |

## 实测（2026-10-02，首次交付；数字均为本轮现算）

- **16 项测试双入口同数**（`discover` 与直跑均 16 OK）；`run.bat` **两次退出码 0**、
  **无任何新增文件**、两次日志经 `tools/logdiff.py` 规范化后**逐字相同**
  （各 121 行；规范项 = 基准 ms 3 处 + unittest 计时 1 条）。
- 核验：**5 个候选、24 处文件行数、9 个探针**全部现算通过；三条负面对照
  （改错行数/探针期望/假锚点）全红。
- 本机基准（60 次中位数，8KB 记录）：**plain ≈ 0.40 ms / +fsync ≈ 0.76 ms**——
  「提交即持久」的边际成本 ≈ 0.36 ms/条（本机介质相关，demo 每次现算）。

## 坑（都留了钉子）

1. **"计数=0"必须有语境的 0**：裸写"fsync 出现 0 次"能骗过任何检查——所以探针规则先要求
   **glob 真匹配到文件**，再说计数；`test_glob_without_match_turns_red` 钉住这条。
2. **行数是最便宜的防漂移锚**：比"我说大概七百行"强得多——重算一次就知道代码有没有被动过；
   修改代码的人会立刻面对"去更新 seeds.json"这一显式动作。
3. **基准数字不能进核验器**：fsync 时间每次不同，塞进"必须相等"的检查会变成 flaky——
   所以基准放 demo【实测】+ logdiff 规范化，核验器只管确定性事实（行数/计数/import）。

3. 若你选定了一个候选：先跑 `run.bat` 存下基线日志，开题后每轮用它核对
   "行数与探针"的变化幅度——这正是 B39 记录模板里"证据"一节的手感。
