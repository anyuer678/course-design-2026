# B13-tinylang —— 编译原理：一条能完整追踪的流水线

课程映射：**编译原理**。把教材的六个阶段真的串成一条链，并且每一段都能单独看清楚：

```
源码 → 词法 → 语法(AST) → 语义检查 → 字节码 → 虚拟机 → 输出
              ↑ 每一层都带源码行列，报错能指到真正的字符
```

语言叫 `tiny`：静态类型、有块作用域、有 `if/else` 与 `while`，**没有函数**（函数与调用帧明确留作扩展）。
它小是为了让"整条链"看得见，不是为了好看——每个阶段都有独立测试，
最后再用**两条完全不同的执行路径互相**对拍（字节码 VM vs 树遍历解释器，300 个随机程序）。

## 运行

```
run.bat                                   # 自测（55 项 + 393 subTest）+ 9 个样例程序 + 演示，约 5 秒
python tests\test_tinylang.py             # 逐层单测：词法/语法/语义/代码生成/VM
python tests\test_against_reference.py    # 随机程序对拍：VM vs 树遍历
python demo.py                            # 六段演示（全链逐阶段 → 语义选择 → 错误定位 → 对拍）

python tiny.py programs\gcd.tiny                  # 跑
python tiny.py programs\gcd.tiny --tokens         # 只看词法
python tiny.py programs\collatz.tiny --ast        # 只看 AST
python tiny.py programs\gcd.tiny --asm            # 只看字节码与常量池
python tiny.py programs\gcd.tiny --trace          # 看执行轨迹（pc / 行号 / 栈顶 / 变量）
python tiny.py programs\error_types.tiny          # 看语义怎么一次报全
python tiny.py -c "let x : int := 1.5;"           # 一句话试错
```

`tiny.py` 退出码：**0** 正常、**1** 运行期错误、**2** 编译期错误、**3** 用法/读文件问题。
`run.bat` 会**断言**三个故意写错的样例分别以 2 / 2 / 1 退出——报错被吞掉等于没报错。

## 课程章节 ↔ 代码 ↔ 怎么验

| 教材章节 | 本项目对应 | 关键做法 | 验证方式 |
|---|---|---|---|
| 词法分析 | `lexer.py` | 手工扫描而非正则：行列由自己推进；记号自带 Span | `TestLexer` 断言跨行/跨块注释后的**具体列号**，8 类词法错误的行列 |
| 文法与语法分析 | `parser.py` | EBNF 递归下降 + 每级一个函数的优先级链 | `TestParserShapes` 用 s-表达式**断言树形**（`1+2*3` → `(+ 1 (* 2 3))`） |
| 符号表与作用域 | `semantics.py` | 作用域栈 + 槽位单调分配；块内可遮蔽 | 遮蔽、自引用初始值、`let` 位置约束都有专门用例 |
| 类型检查 | `semantics.py` | 只有 int→real 自动加宽；bool 不当数字 | 14 条类型规则用例逐个断言，含"错误级联不刷屏" |
| 中间代码 / 目标代码 | `codegen.py` | 栈机指令；跳转先占位后回填 | 断言 `JZ/JUMP` 目标**已回填且不越界**、`I2F` 该有就有不该有就无 |
| 运行时存储组织 | `vm.py` | 定长局部槽位数组 + 操作数栈 | 手工构造非法指令，验证防线（栈下溢、越界槽位、坏常量索引） |
| 错误处理 | `spans.py` 起 | 每阶段错误带 Span；语义一次收全 | 断言 4 处错误的行号顺序与渲染插入符位置 |
| 解释器/编译器一致性 | `tree_walk.py` + `fuzz.py` | 两套完全不同的后端 | 300 个随机程序输出与全局状态逐字节一致 |
| 代码优化 | **没做** | 常量折叠是练习 4 | `codegen` 只把 `-2` 这类负字面量折进常量，不做表达式折叠 |

## 语言定义（每个选择都写下来，不留"你猜"）

```
program  := stmt*
stmt     := "let" ident ":" type ":=" expr ";"
          | ident ":=" expr ";"
          | "print" expr ";"
          | "if" expr "then" stmt ["else" stmt]
          | "while" expr "do" stmt
          | "{" stmt* "}"
type     := int | real | bool | string
expr     := or_expr                       # 见下面的优先级表
```

优先级（低 → 高）：

```
or  →  and  →  not(前缀)  →  比较(= != < <= > >=)  →  + -  →  * / %  →  一元 -  →  primary
```

* 比较**同级且不可连用**：`1 < 2 = true` 是语法错误，要写 `(1 < 2) = true` 或 `1 < 2 and ...`。
* `not` 比比较松：`not a = b` 是 `not (a = b)`；一元 `-` 比 `*` 紧：`-2 * 3` 是 `(-2) * 3`。
* 括号不产生 AST 节点（优先级已编码进树形）。
* dangling `else` 归最近的 `if`。
* `let` 只能出现在程序顶层或 `{ }` 块里，**不能**直接当 `if/while` 的语句体
  （那样符号会登记到外层、槽位却只在分支执行时才有值）。

类型与运算规则（**这些是语言决定，不是自然规律**）：

| 规则 | 选择 | 为什么 |
|---|---|---|
| 自动转换 | 只有 `int → real`，且由代码生成发出**可见的 `I2F` 指令** | 加宽在字节码里看得见，才不会被"类型系统偷偷改了值"绕过去 |
| `real → int` | 拒绝 | 截断有 floor / round / 向零三种合法答案，必须由程序员选 |
| `bool` | 不参与算术，不与数字比较，不加宽成 real | `true + 1` 是历史事故高发区 |
| `/`、`%`（两边 int） | **floor** 语义：`-7/2 = -4`、`-7%2 = 1` | 与 Python 一致；C/Java 的向零截断会给 -3、-1，测试把两种都算过 |
| `/`、`%`（含 real） | 普通浮点除法 / floor 取模 | 与整数保持一套故事 |
| 字符串 | 只支持 `+`（两边都得是 string）与 `= !=` | 字典序要先规定编码顺序，不默认自己会选对 |
| 条件 | 必须是 `bool`；`if 1 then` 是错误 | 不把非零当真 |
| `and` / `or` | **真短路**（JZ/JNZ + 补丁） | `x != 0 and 10 / x > 1` 在 x 为 0 时不许算除法 |
| `print` | 吃任何类型；real 用最短往返表示（`repr`） | `0.1 + 0.2` 打印成 `0.30000000000000004`，不假装它是 `0.3` |

硬上限（超限就报错，不做"尽力而为"）：源码 256 KiB、表达式嵌套 64 层、语句 100 000 条、
一次最多报 40 条语义错误、执行步数默认 200 000（`--max-steps` 可调）。

## 一条程序的旅程（下面是 `demo.py` 的真实输出，不是示意图）

```
let i : int := 1; ... while i <= n do { sum := sum + i * i; i := i + 1; } print sum;
```

字节码（每条都带源码行号，反汇编按行分段）：

```
  ;; 第 4 行: while i <= n do {
    6  LOAD   2
    7  LOAD   0
    8  CMP    <=
    9  JZ     21                    ← 目标 21 = "print sum" 的第一条，回填过
  ;; 第 5 行: sum := sum + i * i;
   10  LOAD   1
   11  LOAD   2
   12  LOAD   2
   13  BIN    *
   14  BIN    +
   15  STORE  1
   ...
   20  JUMP   6                     ← 回到条件求值
   21  LOAD   1
   22  PRINT
   23  HALT
```

执行轨迹（`--trace`）：

```
   0  行1   PUSH   0      ; 6   栈顶=None   变量=[None, None, None]
   1  行1   STORE  0          栈顶=6       变量=[None, None, None]
   6  行4   LOAD   2           栈顶=None      变量=[6, 0, 1]
```

三个"故意写错"的样例输出：

```
error_syntax.tiny  → 1 条语法错误，第 3 行第 7 列，插入符指着 int（缺的是冒号）
error_types.tiny   → 4 条语义错误，按行号 3/4/5/6 排好，一次全报出来
error_runtime.tiny → 语义全对、运行期炸：第 8 行 除数为 0（12 除以 0 没有定义）
```

## 正确性论证（每阶段"为什么可以这样干"）

* **词法**：`_advance` 是唯一改变行列的地方，且对 `\n`、`\r\n`、`\r` 三种换行分别处理。
  任何记号的列号都等于"起始列 + 已消耗字符数"，这是可测试的等式，`TestLexer` 就是在测它。
* **语法**：优先级链的不变式是"`parse_X` 返回的树，其顶层运算符不高于 X 级"。
  每级一个函数、循环消费同级左Operator，就是左结合的由来；比较级在消费一次后
  主动检查后随符号，属于同级则报错 —— 于是"不可连用"是**实现里的显式检查**而不是巧合。
* **语义**：`type_of` 返回 `None` 表示"这个子表达式已经报过错"，上层遇到 `None` 就**不再报错**。
  这条规矩保证了"错误级联不刷屏"，同时保证通过检查的程序里每个节点都有类型标注。
  槽位单调分配 + 块内可遮蔽 ⇒ 名字到槽位是**编译期唯一映射**，运行期不再有名字查找歧义。
* **代码生成**：跳转目标一律"先占位、后回填"，回填点只有三处（if 的两个出口、while 的两个出口、
  and/or 的两个出口），每处都有测试断言"参数不为 0 且在指令范围内"。
  负数折叠只发生在字面量上（`-2` → IntLit(-2)），不涉及常量传播，因此不影响其他运算。
* **两个后端一致**：VM 与树遍历在变量表示（槽位 vs 名字字典）、控制流（跳转 vs 递归）、
  短路（JZ/JNZ vs 语言的 and/or）三处刻意不同；共用的是 `values.py` 的运算规则（那是语言定义）。
  300 个随机程序上**输出逐字节一致 + 全局变量终值一致**，才敢说实现没错。

## 踩过的坑（本轮真实记录）

1. **类型名有两套写法，一处不统一就全线假错误**：语法给出的是 `int`，表达式类型内部用 `INT`。
   检查器一比较，16 个正常程序全被判"类型不符"，还连锁导致槽位没分配、后续错误一堆。
   修法是在检查器入口统一大写，而 **AST 里保留用户写的那个词**（`--ast` 打印出来仍是 `int`）。
2. **`list.count(1)` 数出 3 个常量**：Python 里 `1 == 1.0 == True`，常量池"去重"必须按
   `(类型, 值)` 判等，否则 `1`、`1.0`、`true` 会被当成同一个常量——测试里现在直接按类型计数。
3. **VM 把内部错误外包给 Python**：越界常量索引抛 `IndexError`、坏运算码抛 `KeyError`、
   `STORE` 不检查槽位。现在全部换成带行列的自有错误（"读取不存在的常量池下标 99"），
   并且有一条专门手工构造非法指令的测试证明防线存在。
4. **裸 `\r` 不算换行**：CRLF 能过，老 Mac 换行的文件行号会全体错位。`_advance` 现在
   对 `\r\n`、`\r`、`\n` 三种都正确推进（`_` 注释里写明了为什么 `\r` 后面跟 `\n` 时不动行号）。
5. **`let` 直接当 `if/while` 的语句体会造成"名字可见但槽位可能没值"**：符号登记在外层作用域，
   赋值却只在分支执行时发生。改成显式语法规则（`let` 只能在顶层或块里），报错文案说清为什么。
6. **代码生成读检查器的标注**，没标注就抛 `CodegenError`。这条不变式是被"写错的测试"意外验证的：
   我漏了一次 `analyze()`，编译器立刻拒绝工作——**两处各自推类型迟早会不一致**，
   那种不一致表现为"检查通过但运行期炸了"，比直接报错难查一个数量级。
7. **随机语料里的陷阱自己也是代码，也会错**：第一版陷阱写成 `(g+10)/(g+10)`，
   `g == -10` 时合法地除零，3 个 seed 报错——错的是生成器不是后端。陷阱也要被验证。
8. **有 5 处是我的测试期望写错，代码是对的**：记号下标差一位、块注释后的列号（应该是 7 不是 10）、
   语句 span 结束列（分号占一格）、`a + b * c / d` 是 `(/ (* b c) d)` 而不是右结合、
   以及把"缺少右括号"的用例写成程序开头的 `(`（那其实是缺语句）。
   教训与上一轮同源：**期望值必须有出处**，不能靠印象。

## 已知局限（说清楚，不含糊）

* **没有函数**：没有调用帧、参数传递、递归；也就没有作用域的函数层。这是练习 3。
* **没有错误恢复**：语法错误在第一个就停（只报一条）。要做"跳过一句继续分析"必须
  先定义同步集，否则会把后面的错误全变成噪声。这是练习 5。
* **没有代码优化**：常量折叠、复制传播、跳转直达目标都没做；字节码是"直译"，
  为的是让 trace 与源码一一对应，优化会破坏这种对应。
* **类型系统是名义类型、无子类型、无类型参数化**；`int/real` 的加宽是硬编码的一条规则，
  不是通用隐式转换机制。没有 overload，没有联合类型。
* **VM 是栈机、单文件、无模块系统、无异常机制**；运行时错误直接终止程序（没有可恢复错误）。
* **整数是 Python 的任意精度整数**，与真机字长语义不同（不会溢出）；实数是 IEEE double，
  打印用最短往返表示，比较用 `==` —— 浮点相等比较在教育性语言里同样危险，这里没做容差处理。
* **步数上限是唯一的资源护栏**：没有内存上限、没有输出量上限（`print` 循环能刷爆终端）。
* **测试语料由自建生成器产生**：覆盖了我认为重要的构造（循环、分支、遮蔽、短路、混合类型），
  但它不是形式文法的完整覆盖，也不是 fuzzing 意义上的覆盖率证明。

## 练习建议（G2，自己动手）

1. 加内置转换函数 `int(x)`（floor）与 `round(x)`，先决定并写下：`int(-2.5)` 应该等于几，为什么。
   然后把 `x := int(x)` 放进一个原本被拒的程序里，确认它现在通得过、且两个后端结果一致。
2. 给字符串加字典序比较：先写清按什么编码比较、非 ASCII 怎么办，再实现，并补上你自己的反例测试。
3. 加函数与调用帧（`fun f(a : int) -> int { return a * 2; }`）：需要动 AST、语义（形参作用域）、
   代码生成（帧与返回地址）、VM（调用栈）。做完说明为什么"没有函数"时槽位分配能这么简单。
4. 实现常量折叠优化（`1 + 2 * 3` → `7`），并解释它为什么会让 `--trace` 的行对应变模糊、
   怎么在保留可追踪性的前提下做（提示：只折叠，不删除语句的行号标注）。
5. 做语法错误恢复：定义同步集（`;`、`}`、语句起始关键字），跳过到同步集继续解析，
   然后统计"一条程序里 3 个语法错误"能报出几条——并解释为什么会漏报。
