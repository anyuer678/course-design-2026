# B13-tinylang —— 编译原理：一条能完整追踪的流水线

课程映射：**编译原理**。把教材的六个阶段真的串成一条链，并且每一段都能单独看清楚：

```
源码 → 词法 → 语法(AST) → 语义检查 → 字节码 → 虚拟机 → 输出
              ↑ 每一层都带源码行列，报错能指到真正的字符
```

语言叫 `tiny`：静态类型、有块作用域、有 `if/else` 与 `while`，
**有函数与调用帧**（B41 候选②新增：`fun f(a : int) -> int { return a * 2; }`，
调用约定先写成 `docs/frames-spec.md` 再实现）。它小是为了让"整条链"看得见，
不是为了好看——每个阶段都有独立测试，最后再用**两条完全不同的执行路径互相**对拍
（字节码 VM vs 树遍历解释器，300 个随机程序——从候选②起随机语料里也有函数与调用）。

## 语言定义（每个选择都写下来，不留"你猜"）

```
program  := (fun_def | stmt)*
fun_def  := "fun" ident "(" [param ("," param)*] ")" "->" type block
param    := ident ":" type
stmt     := "let" ident ":" type ":=" expr ";"
          | ident ":=" expr ";"
          | "print" expr ";"
          | "if" expr "then" stmt ["else" stmt]
          | "while" expr "do" stmt
          | "return" expr ";"
          | "{" stmt* "}"
type     := int | real | bool | string
expr     := or_expr                       # 见下面的优先级表
primary  := … | ident "(" [expr ("," expr)*] ")"      # 函数调用
```

优先级（低 → 高）：

```
or  →  and  →  not(前缀)  →  比较(= != < <= > >=)  →  + -  →  * / %  →  一元 -  →  primary
```

* 比较**同级且不可连用**：`1 < 2 = true` 是语法错误，要写 `(1 < 2) = true` 或 `1 < 2 and ...`。
* `not` 比比较松：`not a = b` 是 `not (a = b)`；一元 `-` 比 `*` 紧：`-2 * 3` 是 `(-2) * 3`。
* 括号不产生 AST 节点（优先级已编码进树形）。
* dangling `else` 归最近的 `if`。
* `let` 只能出现在程序顶层或 `{ }` 块里，**不能**直接当 `if/while` 的语句体。

函数（完整口径见 `docs/frames-spec.md`，这里只列结论）：

* **先定义后使用**：自递归可以（定义体内自身可见），**互递归不行**（要前向声明，不做）。
* 函数名与变量名**禁止重名**；函数体**看不到全局变量**（只有形参 + 自身局部）。
* `return` 只在函数体内；实参个数/类型必须匹配（int→real 是唯一加宽）；返回值同理。
* **缺 return 是运行期错误**（不做"所有路径都 return"的静态流分析——
  要做就得先定义一个完整的控制流分析，这里诚实不装）。
* **调用深度上限 100**（顶层是第 0 层）；超过由两个后端报同一句话。
* 没有 void 函数、没有裸调用语句：调用是表达式，值必须被使用。

类型与运算规则（**这些是语言决定，不是自然规律**）：

| 规则 | 选择 | 为什么 |
|---|---|---|
| 自动转换 | 只有 `int → real`，且由代码生成发出**可见的 `I2F` 指令**（实参与返回值同理） | 加宽在字节码里看得见，才不会被"类型系统偷偷改了值"绕过去 |
| `real → int` | 拒绝 | 截断有 floor / round / 向零三种合法答案，必须由程序员选 |
| `bool` | 不参与算术，不与数字比较，不加宽成 real | `true + 1` 是历史事故高发区 |
| `/`、`%`（两边 int） | **floor** 语义：`-7/2 = -4`、`-7%2 = 1` | 与 Python 一致；C/Java 的向零截断会给 -3、-1，测试把两种都算过 |
| `/`、`%`（含 real） | 普通浮点除法 / floor 取模 | 与整数保持一套故事 |
| 字符串 | 只支持 `+`（两边都得是 string）与 `= !=` | 字典序要先规定编码顺序，不默认自己会选对 |
| 条件 | 必须是 `bool`；`if 1 then` 是错误 | 不把非零当真 |
| `and` / `or` | **真短路**（JZ/JNZ + 补丁） | `x != 0 and 10 / x > 1` 在 x 为 0 时不许算除法 |
| `print` | 吃任何类型；real 用最短往返表示（`repr`） | `0.1 + 0.2` 打印成 `0.30000000000000004`，不假装它是 `0.3` |

硬上限（超限就报错，不做"尽力而为"）：源码 256 KiB、表达式嵌套 64 层、语句 100 000 条、
一次最多报 40 条语义错误、执行步数默认 200 000（`--max-steps` 可调）、
**调用深度 100 层**（`runtime.py` 里一处定义，两后端共用）。

## 一条程序的旅程（下面是 `demo.py` 的真实输出，不是示意图）

`while` 版（求和）的字节码片段与轨迹见 `demo.py` 第 1 段。函数版（`fib`）：

```
    ;; 第 5 行: print fib(10);
      1  CALL   0      ; fib            ← CALL 的参数是函数表下标，注释给出名字
    ;; 第 2 行: if n < 2 then return n;
      9  RET                           ← return 走操作数栈（返回值通道）
    ;; 第 3 行: return fib(n - 1) + fib(n - 2);
     13  CALL   0      ; fib
     17  CALL   0      ; fib
     19  RET
    ;; 第 4 行: }
     20  NORET                         ← 体尾落点保护：走到这里 = 缺 return
```

执行轨迹（`--trace`）每一步都带**调用深度**：

```
      4  行2   LOAD   0           栈顶=None   变量=[10] 深度=1
     10  行3   LOAD   0           栈顶=None   变量=[10] 深度=1
```


## 正确性论证（每阶段"为什么可以这样干"）

* **词法**：`_advance` 是唯一改变行列的地方，且对 `\n`、`\r\n`、`\r` 三种换行分别处理。
  任何记号的列号都等于"起始列 + 已消耗字符数"，这是可测试的等式，`TestLexer` 就是在测它。
* **语法**：优先级链的不变式是"`parse_X` 返回的树，其顶层运算符不高于 X 级"。
  每级一个函数、循环消费同级左Operator，就是左结合的由来；比较级在消费一次后
  主动检查后随符号，属于同级则报错 —— 于是"不可连用"是**实现里的显式检查**而不是巧合。
* **语义**：`type_of` 返回 `None` 表示"这个子表达式已经报过错"，上层遇到 `None` 就**不再报错**。
  这条规矩保证了"错误级联不刷屏"。函数的加入没有破坏它：调用检查在函数的
  "独立槽位空间 + 全局遮罩"里进行，通过检查的函数里每个节点都有类型与槽位标注。
* **代码生成**：跳转目标一律"先占位、后回填"，回填点只有三处（if 的两个出口、while 的两个出口、
  and/or 的两个出口），每处都有测试断言"参数不为 0 且在指令范围内"。
  函数体排在主线 HALT 之后，`CALL` 携带函数表下标（entry 是函数表项在体生成完时填的），
  所以主线里的调用**不需要回填**。
* **两个后端一致**：VM 与树遍历在变量表示（槽位 vs 名字字典）、控制流（跳转 vs 递归）、
  短路（JZ/JNZ vs 语言的 and/or）、调用（显式帧栈 + CALL/RET vs 整体换作用域 + 宿主异常）
  四处刻意不同；共用的是 `values.py` 的运算规则与 `runtime.py` 的错误文本（那是语言定义）。
  300 个随机程序上**输出逐字节一致 + 全局变量终值一致**，才敢说实现没错。
* **调用帧的深度护栏**：上限 100 在**压入前**检查（两边口径相同：第 101 层被拒）。
  树遍历用的是 Python 递归，每个调用层消耗若干宿主栈帧——所以 `interpret()` 入口把
  `sys.setrecursionlimit` 临时提到"上限 × 每层最坏帧数 + 余量"（每层最坏 ≈ 2 × 64 + 常数，
  64 是解析器钉死的表达式嵌套上限），跑完恢复。**这不是防患于未然**：实测不提升时，
  深表达式 + 递归在约 7 层就被 `RecursionError` 抢先——报的是宿主错误、深度也不对。
  VM 侧是显式帧栈（迭代主循环），天然没有这个问题——两边的护栏机制不同，可观察行为相同。

## 函数与调用帧（B41 候选②，2026-10-02）

本轮把"函数与调用帧明确留作扩展"这条旧局限落成了实现。做法上有一条硬规矩：
**调用约定先写纸上再动手**（`docs/frames-spec.md`：帧布局、返回值通道、深度上限、
逐字错误文本表），两份实现只做翻译——两条后端各错一半却"看起来对拍通过"是最难查的结局。

* **帧布局**：形参占槽位 `0..arity-1`，函数体内的局部从 `arity` 起独立分配；
  每个函数的 `locals_count` 是"一个帧的总槽数"，与主线全局槽位互不相干。
* **调用序列**：实参从左到右求值压栈 → `CALL i` → VM 弹出实参填新帧、
  保存（返回地址、调用者帧）→ 跳入口；`RET` 弹返回值、恢复调用者帧、把值压回操作数栈。
* **递归样例与互证**：`programs/fib.tiny`（对迭代参照）、`hanoi.tiny`（对 Python 递归参照
  与 2^n-1 性质）、`ackermann.tiny`、`binomial.tiny`（对 `math.comb`）——
  见 `tests/test_recursion.py`。**快排不在其中**：本语言没有数组，序列类算法写不出来；
  不假装测过，它在练习里（先加数组与越界检查）。
* **随机语料**：生成器每个程序先造 1–3 个函数（函数体只调用更早定义的函数，调用图无环 →
  运行必终止），300 个随机程序**全部**含调用，两后端逐字节一致。

## 踩过的坑（本轮与历史的真实记录）

1. **类型名有两套写法，一处不统一就全线假错误**：语法给出的是 `int`，表达式类型内部用 `INT`。
   修法是在检查器入口统一大写，而 **AST 里保留用户写的那个词**。
2. **`list.count(1)` 数出 3 个常量**：常量池"去重"必须按 `(类型, 值)` 判等。
3. **VM 把内部错误外包给 Python**：越界常量索引、坏运算码、`STORE` 不检查槽位——
   现在全部换成带行列的自有错误，并有手工非法指令测试证明防线存在。
4. **裸 `\r` 不算换行**：CRLF 能过，老 Mac 换行的文件行号会全体错位。
5. **`let` 直接当 `if/while` 的语句体会造成"名字可见但槽位可能没值"**：改成显式语法规则。
6. **代码生成读检查器的标注**，没标注就抛 `CodegenError`——这条不变式被"写错的测试"意外验证过。
7. **随机语料里的陷阱自己也是代码，也会错**：第一版陷阱 `(g+10)/(g+10)` 在 `g == -10` 时合法除零。
8. **有 5 处是我的测试期望写错，代码是对的**。教训：**期望值必须有出处**，不能靠印象。
9. （候选②）**词法漏了逗号**：`fun f(a : int, b : int)` 一写就报"无法识别的字符 ','"——
   加 `fun`/`return` 关键字和 `->` 时忘了把 `,` 加进运算符表。解析 `hanoi.tiny` 的冒烟当场抓出。
10. （候选②）**"函数看不到全局"只写在文档里是不够的**：第一版 `lookup` 仍然穿透到全局作用域，
    检查器放行了 `fun f() -> int { return g; }`。修法是给检查器加 `visible_floor` 遮罩，
    并补上"引用全局必须报错"的测试。**规则要落实成数据结构，不能只写在注释里**。
11. （候选②）**树遍历的宿主栈护栏不是装饰**：不提升 `sys.setrecursionlimit` 时，
    25 层右嵌套表达式 + 递归在约 7 层调用深度就被 Python `RecursionError` 抢先。
    已实测两种跑法（直接 `TreeWalker` 炸、经 `interpret()` 正常）并写进对拍测试。
12. （候选②）**参照实现自己也会错**：手写 Python 版 Ackermann 参照把 `A(m, n-1)` 敲成
    `A(m, n)`，测试一跑就 `RecursionError`——和坑 7、8 同源：**验别人之前先验参照**。
13. **GBK 扫描第四次复发**：这次扫出的是历史遗留的三个符号字符——对勾、叉号、双向箭头
    （都不在 GBK 里），统一换成 `√`/`×`/`与`。教训不改：每轮动过的文件都要过一遍扫描器。

## 已知局限（说清楚，不含糊）

* **没有数组**：序列类算法（快排、归并排序……）无法表达——这是练习 1 的主题。
* **没有互递归**：单遍"先定义后使用"，前向声明没做；嵌套函数、一等函数、默认参数、
  可变参数、泛型参数、void 函数都不在语言里。
* **缺 return 是运行期错误**：不做"所有路径都 return"的静态流分析（那要先有控制流分析，
  现阶段不装）。声明 `-> int` 却漏写 return 的程序能编译，跑到结尾才报。
* **调用深度上限 100** 是硬编码护栏（`runtime.py`），深递归的正确程序会被拒——
  这是教学语言的选择：宁可拒绝，不让宿主栈决定行为。树遍历侧的宿主栈上界
  依赖"表达式嵌套 ≤ 64"这个解析期保证，CPython 3.12 实测安全（3.10 及以下有 C 栈压力）。
* **没有错误恢复**：语法错误在第一个就停（只报一条）；运行期错误直接终止程序。
* **没有代码优化**：常量折叠、复制传播都没做；字节码是"直译"，为的是 trace 与源码一一对应。
* **整数是 Python 的任意精度整数**，与真机字长语义不同（不会溢出）；实数是 IEEE double，
  打印用最短往返表示，浮点相等比较没做容差。
* **步数上限是唯一的执行护栏**：没有内存上限、没有输出量上限（`print` 循环能刷爆终端）。
* **测试语料由自建生成器产生**：覆盖了循环、分支、遮蔽、短路、混合类型、函数调用，
  但它不是形式文法的完整覆盖，也不是 fuzzing 意义上的覆盖率证明。
