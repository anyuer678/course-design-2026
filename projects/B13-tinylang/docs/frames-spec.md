# 函数与调用帧：先在纸上定死的调用约定（B41 候选②）

这份文档**先于实现**写出（2026-10-02）。理由来自本轮候选风险评估里的一句话：
两条后端（字节码 VM 与树遍历参照解释器）的调用约定如果不能逐条对齐，
对拍会陷入「两边各错一半、对拍却看不出」或「两边都没错、错误消息却对不上」两种泥潭。
所以帧布局、返回值通道、深度上限、错误文本都先在这里定死，实现只做翻译；
实现完成后本文不再改动——若实现与本文不符，以本文为准，改实现。

## 一、语法（在原有文法上的增量）

```
program := (fun_def | stmt)*
fun_def := "fun" ident "(" [param ("," param)*] ")" "->" type block
param   := ident ":" type
stmt    := …原有五种… | "return" expr ";"
primary := …原有… | ident "(" [expr ("," expr)*] ")"     # 函数调用
```

* `fun` 与 `return` 升为关键字；`->` 是一个运算符记号，词法扫描时必须排在 `-` 前面。
* 函数定义只能出现在**顶层**，不能嵌套在块里；可以穿插在顶层语句之间。
* 调用实参**从左到右**求值；先全部求值、再进帧。
* 没有裸调用语句：调用是表达式，值必须被使用（`print f(x);` / `let y := f(x);`）。
  本语言没有 void 函数——不引入「丢弃返回值」的语句形式（见表末"不做"）。

## 二、名字规则（单遍检查，先定义后使用）

1. 函数从它的定义处开始可见；检查函数体时它自己已登记，因此**自递归天然可用**。
2. **互递归不支持**：f1 的函数体里不能调用后面才定义的 f2。
   想支持需要前向声明或两遍登记，明确不做（列为练习，并写清代价）。
3. 函数名与变量名是两个命名空间，但**禁止重名**：任何变量（顶层 `let`、函数体内的
   `let`、形参）与任何函数同名都是语义错误。规则简单好解释，胜过多半层查找规则。
4. **函数体看不到全局变量**：函数的作用域只有形参 + 自身局部。没有全局变量、没有闭包。
   这一条让「一个帧装得下函数能看到的一切」成立——帧模型干净是这一轮的核心收益。
5. `return` 只能出现在函数体内；函数外出现是语义错误（顶层 `return` 同样被拒）。
6. 函数名当值用（`print f;`、`x := f;`）是语义错误；调用一个变量的名字（`x(1)`）也是。
7. 实参个数必须等于形参个数；实参类型必须可赋给形参（**int → real 是唯一加宽**，
   与赋值同一套规则）；返回值类型同理必须可赋给声明的返回类型。

## 三、帧布局与调用/返回（VM 口径，定死）

* 每个函数一个**编号**（按定义顺序，从 0 起）。`Code.functions` 是函数表：
  `FunctionInfo(name, entry, locals_count, arity, param_types, return_type)`。
* **帧布局**：形参占槽位 `0..arity-1`（按书写顺序）；函数体内的局部变量从 `arity` 起
  单调分配（块内遮蔽照旧分配新槽位）。`locals_count` 是「这个帧的总槽数」，
  它与主线程序的 `locals_count`（全局槽位）互不相干、各自独立从 0 计。
* **调用序列**：实参从左到右求值压入操作数栈 → `CALL i` → VM 弹出 arity 个值填进新帧
  的 `0..arity-1`（先弹的填后面的槽位）→ 把（返回地址 pc、调用者帧、函数编号）压入
  调用栈 → pc 跳到 `functions[i].entry`。
* **返回序列**：`return e;` 编译为「求值 e（按返回类型加宽，int→real 补 I2F）→ `RET`」。
  `RET` 弹出返回值，恢复调用者帧与返回地址，把返回值压回操作数栈——
  **调用的结果是表达式，返回值走操作数栈通道**，此后调用点继续做它所在的表达式。
* **落点保护**：函数体末尾编译器**总是**补一条 `NORET`（以 return 结尾时不可达，也无害）。
  执行到 `NORET` 就是「缺 return」运行期错误；它同时把函数体与下一个函数体隔开，
  执行流不存在「落入下一个函数」的可能。
* **布局**：主线代码在前，函数体按定义顺序排在主线 `HALT` 之后；只有 `CALL` 能进入函数体。
  `CALL` 的参数是**函数编号**（不是地址），所以主线发出 CALL 时不需要回填——
  entry 是函数表项在函数体生成完时填写的。
* 主线程序里 `RET` 是非法状态（调用栈为空），由 VM 的防御性检查报错（见 §六）。

## 四、树遍历口径（机制刻意不同，可观察行为必须相同）

* 作用域栈（名字 → 值字典）代替槽位；调用 = 保存当前作用域栈、换成「形参一个作用域」、
  用 Python 递归执行函数体；返回 = 专用异常 `_ReturnSignal`（用宿主语言自身的控制流实现，
  与 VM 的 RET 指令是两套机制——这正是"两条路互相证明"的价值所在）。
* 函数体自然执行完而没有触发信号 → 报**同一个**「缺 return」错误（消息、行号逐字相同）。
* 深度计数：VM 数自己的调用栈长度，树遍历数自己的递归层数；两边都**在压入前检查**，
  第 101 层（上限 100）的调用在**发起处**被拒绝，消息逐字相同。
* 参数求值顺序两边一致（左到右）；实参求值发生在**进帧之前**，因此实参表达式里的
  错误行号属于调用者一侧的源码——这一条有专门的对拍测试。

## 五、深度上限与宿主栈保护

* 上限 `DEFAULT_MAX_CALL_DEPTH = 100`（顶层程序算第 0 层，函数嵌套最多 100 层）。
* VM 是显式帧栈（迭代主循环），上限只是语言护栏；**树遍历用的是 Python 递归**——
  每个 tinylang 调用层要消耗若干 Python 栈帧（每层最坏 ≈ 2 × 表达式嵌套深度 + 常数，
  因为解析器已把表达式嵌套钉死在 `MAX_EXPRESSION_DEPTH = 64`）。
  所以树遍历在 `interpret()` 入口把 `sys.setrecursionlimit` **临时提升**到
  `(上限 + 8) × (2 × 64 + 12) + 1000`（若宿主原本更高则不动），执行完恢复原值。
  不提升的话 Python 的 `RecursionError` 会抢先触发——那时报的是宿主错误、深度也不对，
  两条后端的对拍口径就破了。本机环境 CPython 3.12：纯 Python 递归的帧对象在堆上，
  一万六千层安全（3.10 及以下运行会有 C 栈压力，不在本项目支持范围）。
* 深度限制是两条后端**可观察行为的一部分**：无限递归的程序两边必须在第 100 层、
  同一行、同一句话上停住（有专门的对拍测试钉住）。

## 六、错误文本（逐字，两引擎共用构造器 `tinylang/runtime.py`）

`runtime.py` 存放上限常数与错误构造器，防止两处各写一遍后慢慢漂走。

| 场合 | 消息（逐字） | 位置口径 |
|---|---|---|
| 超过深度上限 | `调用深度超过上限 100：函数 'f' 的第 101 层调用被拒绝（很可能是无限递归）` | 调用点所在行 |
| 缺 return | `函数 'f' 执行到了函数体结尾也没有遇到 return（返回类型 int）` | 函数体结尾（`}` 所在行） |
| RET 时调用栈空 | `RET 被执行时调用栈是空的（代码生成有误，或手工构造的非法指令）` | 该 RET 指令的行号 |
| CALL 编号越界 | `调用了不存在的函数编号 7` | 该 CALL 指令的行号 |

* 深度上限与缺 return 两种错误两引擎共用 `runtime.py` 里的构造器，消息与提示语逐字相同；
  位置只承诺**行号**对齐（列号两引擎不承诺一致，对拍测试断言行号与消息）。
* RET 空栈、CALL 越界、入口越界、帧槽越界是 VM 的防御性检查（对应"手工构造非法字节码"
  的防线测试），消息只在 vm.py 里、不承诺跨引擎——树遍历不存在这些状态。

## 七、明确不做的（本期边界，不含糊）

* 互递归、前向声明、嵌套函数定义；函数作为值（一等函数/函数指针）。
* 默认参数、可变参数、泛型参数（参数就是具体类型）。
* void 函数与裸调用语句（调用即取值，必须被使用）。
* 「所有路径都有 return」的静态流分析：缺 return 是**运行期**错误（诚实实现，不做假检查）。
* 数组与字符串下标：因此快排这类需要序列的算法无法表达——快排列为练习
  （"先加数组与越界检查，再写快排"），本轮的递归互证用斐波那契/汉诺塔/欧几里得/
  Ackermann/二项式系数完成。
