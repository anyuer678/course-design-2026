# B9-os-sim —— 操作系统模拟器

**课程映射**：操作系统原理

五大模块：CPU 调度（FCFS/SJF/优先级/RR + 甘特图）、页面置换
（FIFO/LRU/Clock/OPT + Belady 异常实验）、银行家算法（安全序列 + 请求
判定）、FAT 文件系统模拟（显式链接分配）、生产者-消费者（std::thread +
条件变量的有界缓冲区）。

## 运行

```
run.bat                       # 自测 + 全模块演示
build\os-sim.exe sched        # 单独看某个模块
mingw32-make test             # 183 项断言（MinGW 下 make 命令名是 mingw32-make）
```

## 教科书数字（考试直接用）

参考串 `1 2 3 4 1 2 5 1 2 3 4 5`：

| 帧数 | FIFO | LRU | Clock | OPT |
|---|---|---|---|---|
| 3 | 9 | 10 | 9 | 7 |
| 4 | **10**（Belady！） | 8 | 10 | 6 |

调度（P1[0,7] P2[2,4] P3[4,1] P4[5,4]）：FCFS 平均等待 4.75；SJF 4.0；
RR q=2 平均等待 5.0（甘特图 9 段，见 demo 输出）。

## 实现时踩到的坑

1. **LRU ≤ FIFO 不是定理**：两者互不支配（上面的例子 LRU=10 > FIFO=9）。
   能断言的只有 OPT ≤ 任何算法。第一版测试就断错了。
2. **RR 的入队顺序约定**：新到达进程先入队、再到期进程回队尾。
   顺序反过来，甘特图就完全不同——考试时先写清约定。
3. **等待时间 = 周转时间 - 突发时间**：手算时最容易漏掉减 burst。
4. **分配器必须"边分配边占位"**：`alloc_one()` 只扫描 `fat_[b] == FREE` 却忘了
   把这块标成已用，于是同一个块 0 被连续分配给链上的每一环，`fat_[0]` 自指成环，
   写第二个块时沿链走到 `EOF_MARK` 直接越界崩溃。真实 FAT 里"分配"这个动作
   本身就是一次写盘——**空闲判定和占用标记必须原子地做完**。
5. **覆盖写的顺序决定失败时还剩什么**：原来是"先释放旧链、再分配新链"，磁盘满时
   新链分配失败，旧数据却已经还回去了——文件凭空变小甚至丢失，半条新链还占着块。
   改成"先建新链 → 成功后才释放旧链 → 填数据"，并在 `alloc_chain` 内部回滚半条链，
   满盘的 `write`/`append` 才会保持原内容与原空闲块数。
6. **空文件是一条不存在的链**：`write(name, "")` 让首块 = `EOF_MARK`，`append` 里
   `while (fat_[cur] != EOF_MARK) cur = fat_[cur]` 会拿 `EOF_MARK` 当块号去访问 FAT，
   越界未定义行为。空文件只能退化成整文件写。
7. **"总和相等"证明不了不丢不重**：`{1,1}` 和 `{0,2}` 总和相同。生产者-消费者测试
   改成收集全部消息、排序后逐条比对 `all[i] == i`，才能同时抓住丢失、重复和错值。

## 测试策略

- 调度：教材手算例子的甘特图/均值逐数对拍；RR(q=∞) 退化为 FCFS
- 页面置换：教科书四个数值精确断言 + Belady 异常 + 50 组随机串的
  OPT 下界性质 + LRU/OPT 的"帧数单调不增"（栈式）性质
- 银行家：教材例子的安全序列复验、批准/两种拒绝/回滚完整性
- FAT：内容回读、链长、块复用、覆盖写、损坏链检测；另有空文件读写/追加、满盘时
  新建/覆盖/追加三种失败路径的原内容与空闲块守恒、跨文件链不相交（回归）
- 生产者-消费者：逐条消息守恒（排序后 `all[i] == i`，同时抓丢失/重复/错值）+ 水位不越界
