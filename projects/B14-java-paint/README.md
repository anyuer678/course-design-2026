# B14-java-paint —— Java 面向对象：一个能撤销重做的画图程序

课程映射：**Java 面向对象程序设计** + **程序设计基础实践(C++)/Java 项目实践**（同一份代码习惯）。
核心不是"画出漂亮东西"，而是把四件 OO 课上讲的事做实：类体系与多态、事件处理、
**撤销/重做**、以及**不信任外部输入的文件存取**。

## 环境（本机实测，不装任何东西）

| 项 | 观察结果 |
|---|---|
| PATH 上的 `java`/`javac` | Zulu **OpenJDK 21.0.12 LTS**（`C:\Program Files\Zulu\zulu-21`） |
| `JAVA_HOME` | `C:\Program Files\Java\jdk-17` —— **两套 JDK 并存且不一致** |
| 其他 JDK | `C:\Program Files\Java\jdk1.8.0_171`、`C:\Program Files\Microsoft\jdk-21.0.11.10-hotspot` |
| Maven / Gradle | 都没有 |
| 构建方式 | 直接 `javac --release 17` + `java -cp`，无第三方依赖、无网络 |

两套 JDK 并存是这台机器的真实情况，处理方式写进构建里而不是靠运气：
统一 **`--release 17`** 编译，产物在 JDK 17 与 JDK 21 上都实测跑过（像素统计完全一致：红 1160、蓝 834、绿 642）。
不用 Maven 是因为没装、也不需要——一个包结构的纯 Swing 程序，`javac` 足够，
"为了编译一个类去下载 10 MB 构建工具"不划算。**如果后续 B15–B22 需要 Spring，那时再谈装什么。**

## 运行

```
run.bat                 # 五步：编译 → 无头自测 → 离屏演示 → 展示页新鲜度 → 打开窗口（第 5 步提示人工验证清单）
run.bat no-gui          # 前四步跑完就停（含展示页新鲜度；不开窗口，适合远程/CI）

javac --release 17 -encoding UTF-8 -d out\classes @out\sources-main.txt   # 手动编译
java -Djava.awt.headless=true -cp "out\classes;out\test-classes" paint.PaintTests
java -Djava.awt.headless=true -cp out\classes paint.App --demo            # 离屏演示
java -cp out\classes paint.App                                            # 打开窗口
java -Dpaint.data=D:\notes -cp out\classes paint.App                      # 换文档目录
python tools\showcase.py --write       # 重生展示页 web\showcase.html（--check 过期即红；自包含构建 + 真跑自检/离屏演示）
python tests\test_showcase.py          # 9 项展示页测试（直跑单文件）
```

Windows 上 `-cp` 的分隔符是 `;`，Git Bash 里要整体加引号，否则会被当成命令分隔——这条我踩过。

## 类体系

```
paint.model     形状与文档（不 import 任何 Swing 组件类，只用 Graphics2D/Color/Rectangle）
  Point (record)      整数坐标；"点到线段平方距离"也在这
  Shape (abstract)    draw/contains/bounds/translatedBy/serialize + equals/hashCode 骨架
    LineShape RectShape EllipseShape     ← 多态分发就在 draw 与 contains
  Drawing             有序形状列表 + 选中项 + 变更通知（尾部在最上层）
paint.command   撤销/重做
  Command (interface)  AddShapeCommand  RemoveShapeCommand  MoveShapeCommand
  CommandHistory       两条栈 + 深度上限 + 观察者通知
paint.io        文件
  DrawingFormat        文本格式 serialize/parse，问题一次报全（带行号）
  SafeStore            文件名白名单、落点复核、大小上限、原子写
  DrawingFormatException
paint.ui        视图与交互
  Tool / ShapeFactory  工具枚举 + 按工具创建形状
  Painter              render(文档, 预览, Graphics2D, 宽高)：纯函数，可离屏
  PaintCanvas          JPanel + Mouse/Key 监听；真实逻辑在 pressAt/dragTo/releaseAt/pressKey
  PaintFrame           工具栏、状态栏、保存/打开/新建/导出 PNG
paint.App       入口：无参数开窗口，--demo 走离屏
```

依赖方向是单向的：`ui → model/command/io`，`command → model`，`io → model`。
模型层不引用任何 Swing 组件类，所以**全部逻辑都能在没有显示器的机器上测**——
这不是洁癖：正是这条约束让 7054 项自动检查成为可能。

## 三个模式用在哪，以及什么时候别用

| 模式 | 用在哪 | 换来的具体好处 | 什么时候它是多余的 |
|---|---|---|---|
| 命令 | 所有编辑动作 | 撤销/重做只需要"倒着执行"，不必给每个操作手写反向代码 | 只有一两个可撤销操作时，直接写 undo 更省事 |
| 观察者 | 文档变更 → 画布重绘 + 状态栏 + 按钮可用状态 | 新增一个显示组件只 `addListener`，不改编辑代码 | 只有一处需要响应时，直接调用更清楚 |
| 工厂 | 工具 → 形状实例 | 画布代码里没有 `if (tool == RECT) new RectShape(...)`；加图形只改一处 | 只有一种形状、且不会增加时 |

`Drawing` 的通知刻意只有**一个**回调（内容变了）。把"内容变了"和"选中变了"拆开是性能优化，
本项目没有那种性能问题，拆了只会让每个订阅点多一倍判断——**先不拆，理由写在代码注释里**。
`paintAll` 之类"新建不可撤销"同理：撤销它要存整份文档快照，代价大于收益，也写在注释里。

## 文件格式与它的防线

```
pad 1                          ← 魔数与版本，必须是第一个非空行
line x1 y1 x2 y2 #RRGGBB       ← 两个端点
rect x y w h #RRGGBB           ← 左上角 + 非负宽高
ellipse x y w h #RRGGBB
# 以 # 开头的是注释；空行忽略；字段用空白分隔
```

写出来的文件是**人类可改**的，所以按不可信输入对待：

| 防线 | 触发时的表现 |
|---|---|
| 版本必须等于 1 | `不支持的版本 2` —— 而不是"能读一半算一半" |
| 未知类型、字段数不对、非整数、颜色不是 `#RRGGBB` | 逐条报错，**带行号，一次全报**（改一处跑一次太折磨人） |
| 坐标夹在 ±100000、宽高非负且 ≤100000 | 防住 `rect 0 0 99999999999 1` 这种画出天文数字矩形的文件 |
| 形状数 ≤5000、行数 ≤20000、文件 ≤4 MiB | 一个 5 GB 的 `.pad` 不会把堆吃光 |
| 解析失败 | 文档**一处都不改**：解析只喂给临时 Drawing，全通过才 `replaceAll` |
| 宽高写成负数（手改文件常见误用，把 `x2 y2` 当成终点） | 明确报"宽高不能为负"，不猜你的意图 |

文件名与落点（`SafeStore`）：

* 只允许 `[字母数字下划线连字符中文]{1,48} + .pad`（导出图片同理但必须 `.png`）；
  `../x.pad`、`a/b.pad`、`a\b.pad`、`/abs`、`C:\...`、`con.pad`、`nul.pad`、带空格、带大写扩展名一律拒。
* 解析成绝对路径后再确认仍在 `data` 目录内——白名单挡大部分，这一步防以后有人改代码时漏校验。
* 拒绝符号链接；**校验前不做 `trim()`**：先裁掉控制字符再校验，等于把 `\u0001x.pad` 悄悄改名成
  `x.pad` 写进磁盘，你看到的文件名和真实文件名不该不一样（这条是本轮测出来的真 bug）。
* 保存走"临时文件 + `ATOMIC_MOVE`"，只兜 `AtomicMoveNotSupportedException` 这一个具体异常：
  其他 `IOException`（比如磁盘满）必须原样抛，否则会被伪装成"写成功了"。
* **不用 `ObjectInputStream`**：反序列化不可信字节等于把"构造任意对象"的权力交给文件。
  文本 + 白名单字段校验，最坏情况只是解析失败。

## 验证：自动化做了什么，没做什么

`paint.PaintTests`（无框架，一个 main，headless 跑）**7054 项检查**，分 8 组：

| 组 | 内容 |
|---|---|
| 模型 | 反向拖拽的规范化、不可变（`translatedBy` 返回新实例且原对象不变）、三种形状的命中与"退化线段"、`equals`/`hashCode` 一致（`HashSet` 去重实测） |
| 文档与命中 | 重叠时选中最上层、删下方形状后选中索引前移、删选中项则取消选中、越界选择按取消处理、回调里取消订阅不抛 `ConcurrentModificationException`、形状数上限拒收且不写坏文档 |
| 撤销/重做 | 增删移的 undo/redo 序列、重做拿到同一个形状实例、新命令清空 redo 栈、深度上限丢最老且可统计、"文档被整体换掉后撤销必须自检失败" |
| 文件格式 | 往返含负坐标、13 种坏文件逐个拒收、多问题一次报全并带行号、CRLF/裸 CR/注释/缩进注释、形状数上限 |
| 存取防线 | 17 种恶意文件名拒收、中文名放行、`save/load/listDocuments`、原子写不留 `.tmp`、超大写入拒收、符号链接（平台能建才测，建不了就如实标跳过） |
| 离屏渲染像素 | 空白全是背景色、矩形轮廓有像素且中间仍是背景（空心）、预览会被画出、选中框画蓝且取消后消失、**撤销后对应像素真的消失** |
| 交互语义 | 拖拽过程中不改文档、松手才提交、小于阈值的误点不产生命令、移动只产一条命令、Delete/Ctrl+Z/Ctrl+Shift+Z/Ctrl+Y/Esc、不同工具产出不同形状（工厂生效）、非法参数拒绝 |
| 随机 vs 快照 | 20 轮 × 300 步随机操作（画/选/拖/删/撤销/重做），另一侧用**整体快照栈**实现撤销——两条完全不同的实现逐步比对形状列表，专治"撤销栈与文档失同步" |

**展示页（2026-10-03 展示层批次⑩）**：`web/showcase.html` 由 `tools/showcase.py` 现算——
按 run.bat 同命令行自包含构建（`build/` 已 gitignore）再真跑 `PaintTests` 与 `App --demo`，
页内嵌**当场画出来的 PNG**（3404 字节；sha1 确定性：多次运行逐字节相同，测试钉住）与 8 组自检结论；
9 项展示页测试直跑通过。`run.bat no-gui` 两跑退出码 0，规范化日志逐字相同（各 29 行；规范项=PNG 临时文件名 1 处）。

**没有自动化覆盖、必须人工点的部分**（`run.bat` 第 5 步列了清单）：真窗口能否弹出、
工具栏按钮观感与顺序、颜色选择器/对话框、未保存时的关闭确认、拖拽手感、PNG 导出图片是否合眼缘、
鼠标真实事件与键盘焦点（`requestFocusInWindow` 是否真生效）。
我不会替这些打勾：**屏幕级验证在这台机器上不允许自动执行**（我试过用 `Robot` 抓屏，被安全策略拦下，
这个拦截是对的），所以它们只能由你运行一次来确认。能自动化的部分（绘制结果、事件语义、撤销正确性）
我全部自动化了——这样需要人工确认的就只剩"好不好用"，而不是"对不对"。

## 踩过的坑（本轮真实记录）

1. **`run.bat` 里两回踩了 cmd 的静默坑**（都是退出码 0，都不会自己喊出来）：
   ① `echo` 文案里写 `->`，cmd 把它当重定向，当场在项目目录造出一个名叫 `PNG` 的垃圾文件——
   这条规则我上一轮刚写进 PLAN 第 6 节，这轮自己又犯了一次，是"运行前后目录快照对比"抓出来的；
   ② 改结尾提示语时把一句话拆成两行 `echo`，而脚本尾段还留着 `goto :done`，cmd 按字节偏移回读时
   **从一行中文的中间开始执行**，把 `才会出现 …` 当成命令报错，退出码照旧是 0——
   这次是"顺手 `tail` 了一下日志最后几行"才发现的。修法：尾段不用 label/goto，改走 `exit /b 0` 分支，
   且一句话只占一行 `echo`；验收时除了退出码和目录快照，还要看尾行输出真的打印出来了。
2. **`SafeStore` 先 `trim()` 再校验**：`\u0001x.pad` 被裁成 `x.pad` 并放行，
   等于用户输入的名字和真正落盘的名字不同。改成对原样输入校验。
3. **`equals` 写对但 `hashCode` 用数组当键**：`Objects.hash(..., long[])` 用的是数组身份，
   内容相同的两个形状 hashCode 不同 → 放进 `HashSet` 会重复。测试里用 `HashSet` 去重直接抓到，
   改成字符串几何键后一致。
4. **`Graphics2D g.create()` 不 `dispose()`**：每次重绘泄一个图形上下文，短期看不出来。
   规则：`create()` 出来的副本必须自己关掉。
5. **`MoveShapeCommand` 里"移动 0 像素"会被当成一条命令**：用户撤销一次却没见画面变化，
   以为程序坏了。加 `isNoOp()` 并由画布在提交前判掉。
6. **影子模型必须和真实历史用同一个深度上限**：一开始快照栈不限深，
   撤销到 20 步之后两边"能回退多远"不同，比对失去意义。加上同样的 `trim` 后才对齐。
7. **`JPanel` 在 headless 下能构造，`JFrame` 不能**：所以离屏测试只碰面板与 `BufferedImage`；
   这也是模型层不依赖 Swing 组件类带来的直接好处。
8. **`-cp a:b` 在 Windows 上会被 JVM 当成单一路径**：Git Bash 里得写 `"a;b"`；
   第一次跑就 `ClassNotFoundException`，报的是"找不到主类"而不是"路径写错"。
9. 另有几处失败是**我的期望值算错**而代码是对的：把"外接框角落 (1,1)"当成椭圆边框点、
   移动 20×30 后误算成 x=25（其实 30）、把合法的中文名 `点.pad` 放进了"必须拒绝"的名单。
   沿用上轮的规矩：期望值要么现场算一遍，要么由参照实现给。

## 已知局限（说清楚，不含糊）

* **单文档**：没有多窗口/标签页；"新建"会清空历史（不可撤销回来），确认后直接重来。
* **没有图层**：只有一个堆叠顺序（列表尾部在上）；没有锁定/隐藏/重排，也不能框选**多选**，
  一次只能操作一个形状。
* **不能缩放/旋转**：形状只能通过 `translatedBy` 平移。加"拖手柄改大小"要引入第二个几何操作，
  届时 `translatedBy` 应扩成更一般的变换接口——现在不做是因为需求没到，不是没想到。
* 只有三种图形；没有曲线/折线/文字/填充色，线宽固定为全局常量。
* 撤销粒度 = 一次拖拽，符合直觉但不支持"合并连续操作"（例如连撤 5 步想一步回）。
* 文件只支持版本 1，**没有版本迁移器**：将来改格式必须写 upgrade 逻辑而不是"能读一半算一半"。
* 保存/打开没有自动备份、没有冲突检测（两个窗口同时改同一个文件会互相覆盖）。
* PNG 导出是"当前画布内容 + 画布尺寸"，无 DPI/裁剪/透明背景；`ImageIO` 之外没做图像优化。
* 对话框全部走 `JOptionPane`，没有快捷键帮助、没有最近文件列表、没有撤销历史可视化面板。
* **GUI 的"能开、好用"这一层由人工确认**（见上一节），我只承诺离屏与逻辑层是自动验证过的。
* **展示页生成器用到 Python**（仅标准库）：编译/自检/离屏演示三步仍是纯 javac/java；
  生成器在 `build/`（已 gitignore）缓存编译产物，并依赖本机 PATH 上有 javac/java。

## 练习建议（G2，自己动手）

1. 加"拖右下角手柄缩放"：把 `translatedBy` 扩成 `scaledBy(...)`，想清楚矩形和线段各怎么缩放，
   并给撤销/重做补上对应测试（快照模型那条测试可以直接拿来加一步"缩放"操作）。
2. 做多选（框选 + 一次移动/删除）：一条命令要能撤销多个形状，想想 `Command` 接口要不要加复合命令。
3. 加图层：`Drawing` 变成 `List<Layer>`，序列化格式升级到版本 2 并写一个"读 v1 → 转 v2"的迁移器，
   说明为什么"读到不认识的文件就拒"比"尽量猜"安全。
4. 把"新建/打开"也做成可撤销的（快照式命令），并给历史加上"深度可配置 + 状态栏显示还能撤几步"。
5. 用 `jshell` 或改代码，验证 `equals`/`hashCode` 不一致会造成什么后果：把 `hashCode` 故意改坏，
   看哪几条测试先红——这一步能确认你的测试真的在盯着这件事，而不是恰好通过。
