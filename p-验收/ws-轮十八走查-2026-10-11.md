# 轮十八走查 —— 手写 WebSocket（RFC 6455）+ SensorHub 实时曲线（2026-10-11）

## 改动

**netlab（B11 引擎升级）**
- 新增 `netlab/websocket.py`：手写 RFC 6455 服务器侧——accept key（RFC 原向量
  钉住）、101 升级应答、帧编解码（服务器帧不掩码/客户端帧解掩码、126/127 扩展
  长度、分片续帧、ping→pong、close 握手、64KiB 消息上限）。
- `netlab/server.py`：`Conn` 加 ws 槽位；`_handle` 拦截升级请求（Connection:
  Upgrade + Sec-WebSocket-Key 校验，坏握手 400、无路由 404）；`_drain` 升级后
  字节流归帧解析器（含"握手和前几个帧挤同一次 recv"的情况）；`_timeout` 对 WS
  长连接豁免 HTTP 空闲超时（出站推送续命，outbuf 卡死沿用滞留回收）；
  `_tick` 泵 `on_poll`；异常断开回调 `fire_close(1006)`。
- WS 路由匹配做成 `_match_ws` 可覆写方法——webframe 用自己的 `<param>` 规则桥接。

**webframe**
- `MicroApp.ws(rule)` 装饰器；`MicroServer._match_ws` 桥接命名分组参数。

**SensorHub**
- `@app.ws("/ws/live")`：on_message 换订阅并回快照（points+anomalies），
  on_poll 每秒查增量（seq > 已发最大才推）；坏订阅回 `{"type":"error"}`。
- 前端：WS 优先（徽标 ● 实时推送/○ 轮询模式），快照全量渲染、append 滑动窗口
  （封顶 500），断线 3s 自动重连，重连期间 2s HTTP 轮询兜底；渲染统一进
  `drawChart()`，两种数据来源共用。

## 走查抓出的真缺陷（WS 把"新数据"变成硬需求后现形）

1. **sim 重启覆写历史（潜伏数据腐蚀）**：`SensorSimulator.seq` 每次进程从 0
   重数，`INSERT OR REPLACE` 把新读数覆盖进历史旧行——长跑库 MAX(seq) 永不
   前进、gaps 越涨越大（实测 218）。轮十四修的 inject next_seq 只堵了一个口。
   **修根**：引擎装配 sim 时从库 MAX(seq) 断点续传（空库行为不变，B35 钉值
   不受影响）；`test_restart_persistence` 旧断言钉的正是腐蚀语义，已改为钉
   续传语义（25→28 行）。
2. append 消息缺 device/metric 键——前端按订阅匹配丢弃增量（真 socket 测试
   过了但浏览器没推进），补键后 seq 实时前移。
3. 走查脚本"点数增长"判据在 500 封顶滑动窗口下失效——改判末尾 seq 前移。
