# Board —— 画板桌面应用（P7）：B14 引擎原样复用 + 自动备份 + 探活守护

**定位**：把 B14 手写 Swing 画板变成"会被门户管理、丢不了工作"的产品。
B14 已经做完了画图、撤销重做、PNG 导出与全套防线（7106 项自检，拓展轮 2026-10-07
新增画笔/线宽/方向键微调）；它的 README
明说自己"保存/打开没有自动备份"——**产品层就补这一件真能力**，外加给 Studio
门户一个可探活、可启停的服务形态。**引擎零重写**：`paint.*` 全部直接 import。

## 两种形态（一个入口）

```
python launch.py --port 8023     # 服务形态：目录守护 + 探活口 + 看门狗，不开窗
python launch.py --window        # 桌面形态（独立活）：再开 B14 真窗口（PaintFrame 原样复用），
                                 #   并给窗口文档挂节流自动备份——没保存的工作也有一份；
                                 #   不挂看门狗，启动方退出窗口不受影响
python launch.py --managed-window# 门户托管形态（Studio 启动的就是这个）：= --window + 看门狗，
                                 #   门户"停止"时窗口/守护/探活口整链一秒级退出
```

| 部件 | 来源 | 角色 |
|---|---|---|
| 绘图/撤销/存档/PNG | B14 paint.model / command / io / ui | 引擎，零重写（PaintFrame 窗口原样用） |
| BackupStore | board/src（产品层） | 备份仓库 `data/backups/<桶>/<毫秒>.pad`：原子写/白名单复用 SafeStore，内容校验复用 DrawingFormat |
| AutoBackup | board/src（产品层） | 挂在 Drawing 上的节流监听：改完安静 3s 落一份，崩溃前未保存的工作有兜底 |
| BackupDaemon | board/src（产品层） | 目录守护（谁保存了就备份谁，坏文档如实计 corrupt）+ 探活口（回一行活账）+ 父进程看门狗 |
| Cli | board/src（产品层） | 无头驱动：脚本化"画→存→备份→恢复→导出"，每步回 JSON 行（测试与远程演示用） |

## 探活口（与门户同一口径）

连上 `127.0.0.1:<port>` 就回一行现算活账然后关闭：

```
BOARD 8023 OK docs=3 backups=12 corrupt=0
```

在线 = TCP 连得上；数字是当下的文档数/备份总数/被跳过的坏文档数，不是启动时拍死的老值。

## 被门户管理（如实声明）

Studio 停止 = 终止启动器（Python）。`launch.py` 把自己的 pid 传给 java 子进程的
**父进程看门狗**：一秒内确认父进程不在就自觉退出——不留孤儿进程、不留半开探活口。

## 运行

```
run.bat                                   # 编译 + B14 自检（7106 项）+ 双入口测试（12 项）
python launch.py --window                 # 开窗画画（自动备份同步工作）
python compile_support.py --force         # 强制重编
```

窗口观感、拖拽手感、对话框这些**屏幕级体验仍归人工验收**（与 B14 同一口径）；
能自动化的逻辑层全部自动化了。

## 测试策略（12 项 = 1 引擎 + 7 CLI + 3 守护 + 1 启动器契约）

**引擎完好性**：产品编译产物上现跑 B14 PaintTests，钉住"全部通过：7106 项检查，
0 失败"（钉值出处 = B14 README）；**CLI 全链路**：三形状绘制往返（DrawingFormat
逐项一致）、备份→改→恢复（恢复的就是备份那一刻）、轮换账 [1,2,3,3,3]（keep=3
连写 5 份）、节流自动备份（auto-on 挂在改动之前才有事件可听——这条教训写进了
测试注释）、PNG 魔数、坏脚本首错即停带行号 + SafeStore 挡路径逃逸；
**拓展轮 CLI（2026-10-07）**：画笔 scribble 一笔=一个形状（3 采样点）、nudge
微调生效、线宽 w4/w8 尾缀进 .pad 往返；**守护**：
启动即给现有文档兜一份、变更在轮询间隔内接住、坏文档 corrupt 如实计数不带走
守护、看门狗对不存在的父 pid 秒退；**启动器契约**：launch.py 拉起 → 探活 →
终止启动器 → java 一秒级收干净（Studio 集成的完整预演）。

## 已知边界（如实声明）

- 自动备份按"文档"粒度，不做行级差异；恢复 = 整份替换（B14 单文档口径）；
- 守护的首见即备份：守护启动时会给数据目录里已有文档各兜一份（备份的承诺不挑时机）；
- 备份名 = 毫秒时间戳（同毫秒用 lastStamp+1 错峰，同名 = REPLACE = 丢一份）；
- 服务形态不开窗：Studio 一键启停管理的是守护；窗口请 `launch.py --window`
  （headless 环境会明确拒绝开窗，守护照常可用）；
- 观感归用户验收。
